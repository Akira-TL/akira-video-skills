# 视频项目采用共享资产层与单支视频制作层

视频项目把跨视频可复用资产与每一支独立交付视频分开。项目级 `video/INDEX.md` 只在需要多视频导航时存在；每支视频始终位于 `video/videos/Vxxx_<human-label>/` 并拥有自己的 `VIDEO.md`。对象身份只认稳定 V ID，助记后缀只服务人类阅读，Agent / 文件引用不能依赖后缀。

## 目标结构

```text
video/
├── INDEX.md                    # 多视频时可选，只做导航
├── shared/
│   ├── characters/
│   ├── locations/
│   ├── props/
│   ├── references/
│   └── generations/            # 跨视频共享资产的生成任务
└── videos/
    ├── V001_<human-label>/
    │   ├── VIDEO.md            # 本支视频唯一主要制作稿 + 简短当前摘要
    │   ├── scenes/             # 按规模需要时才出现
    │   ├── materials/          # 本支视频专属但可跨镜头复用
    │   ├── generations/
    │   ├── shots/              # 只有个别镜头需要独立资料时才出现
    │   └── edit/               # 真正进入整片后期时才出现
    └── V002_<human-label>/
        └── ...
```

单视频项目可以省略 `INDEX.md`，但仍使用 `video/videos/Vxxx.../VIDEO.md`，不切换成另一种目录形状；项目未来从一支扩展到多支时无需搬迁。

## 单一正式正文

`Vxxx/VIDEO.md` 记录已有要求、来源、约束、改编范围、剧情概要、整片表达、使用资产、场景 / 镜头总览、当前阻塞与下一步。长视频真正需要拆出 `scenes/SCxx.md` 后，详细动作、对白和场内内容只维护在场景文件，`VIDEO.md` 退化为概要、顺序和链接，禁止双写。

小说原文、章节、世界观、品牌资料等上游正文继续由原体系拥有。视频只记录本次改编采用哪些章节 / 版本 / pointer，不把上游原文搬进 `video/` 重新维护。

## 资产归属与版本

人物、地点、道具及其参考图默认视为项目级可复用资产，除非明确是一支短片的一次性素材，或只属于当前视频的特殊服装 / 状态 / 光照。共享资产记录说明对象的设计约束、已有参考版本及适用用途；外部导入的参考图也可以直接成为正式资产，不要求为了统一来源而虚构 Generation。

设计、Prompt 和参考图没有简单的“谁覆盖谁”优先级：设计说明应满足的特征与约束，Prompt 说明某次要求模型生成什么，已确认参考图说明实际采用的视觉外观。生成结果偏离设计时必须选择重新生成，或显式接受并修改设计；不能因为新图片存在就自动改写设计事实。

文本设计依赖 Git 历史，不为每次修改复制 `design_v02.md`；某个 Generation 真正需要追溯当时的设计依据时记录对象 ID 与 Git revision。二进制参考一旦已经打包交付或实际用于生成就不得覆盖，正式使用版本从 `v01` 起；修改、重新生成或少见的人工处理产生新版本。已经完成的 V 必须继续固定它当时实际使用的资产版本，新版本不会静默替换历史制作依据。

## 复杂度按需要出现

默认保持浅层。人物 / 地点 / 道具文件数量不大时直接放在类别目录；只有内容真的影响阅读才升级为对象子目录。简单视频可以在 `VIDEO.md` / 场景镜头表维护全部 Shot，不要求每个 Shot 建文件夹；只有需要独立 Prompt、特殊连续性、专属资料等时才创建独立 Shot 记录。

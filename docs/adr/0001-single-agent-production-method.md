# 单 Agent 以依赖驱动的视频制作流程为主线

Akira Video 采用“一个 Agent 连贯推进一支视频”的生产模型，而不是模拟导演组内部部门交接。Skill 表达专业方法，不一一对应组织岗位、流程阶段或独占文件；`akira-video` 只负责找到 / 新建要处理的视频并进入制作，`video-production` 是唯一流程负责人，按当前真实依赖调用导演、剧本、视觉设计、分镜、摄影、声音、生成、审片和剪辑等方法。

## 已接受的边界

- `video-init` 只初始化必要骨架，不负责询问创意、剧情、时长、广告策略或视觉方向。
- 不建立独立 `video-brief` 流程。单支 `VIDEO.md` 记录用户 / 来源已经提出的要求、硬约束、创意偏好和待确认项；Production / Director 在这些条件下提出方案，不能因为“Brief 不负责创意”而丢掉用户已经给出的创意要求。
- Director 与 Script 按产物一致性分工，不按文件权限分工。导演方法可以发现并落实剧情、动作或对白修改，但正式变化必须写回唯一剧本 / 制作稿来源；`DIRECTOR.md` 不另存一套竞争剧情。
- Visual Design 统一处理人物、地点、道具、虚构机械、整体视觉和需要生成的长期参考，不再把角色、环境、道具、Materials 强行拆成多个必经 Skill。人物 / 地点 / 道具只是同一视觉设计方法中的不同参考区和偏好能力。
- Storyboard 与 Cinematography 可以保持两个专业方法，但共同完善同一份镜头记录：Storyboard 解决“为什么切、展示什么、动作如何衔接、持续多久”，Cinematography 解决“从哪里看、怎样构图 / 运动 / 用光”。二者不是严格前后两个阶段。
- Visual Design 与 Storyboard / Cinematography 迭代协作。只先确定足够的画风、人物辨识特征、核心地点和少量视觉参考，再按具体镜头补所需角度、状态、首尾帧或参考图；不把“所有视觉资产先全部做完”设为分镜前置 Gate。
- 不建立独立 Continuity Skill。计划连续性、实际出口与后续镜头引用维护在同一正式镜头 / 剪辑记录中，Review 负责比较事实和要求，而不拥有另一套连续性状态。
- Review 负责检查符合度、画面 / 声音质量、连续性和返修位置，不拥有“当前采用版”这一事实；最终采用关系由使用结果的正式记录维护。
- 不建立 Runway / Veo / Seedance 等长期模型适配 Skill，也不维护通用 Model Adapter 框架。执行具体模型时根据当前官方资料核验真实能力，模型限制不能反向改写视频事实或镜头目标。

## 专业方法边界

目标 Skill 拓扑围绕一个流程负责人和一组按需方法收敛：

- `akira-video`：视频项目入口，只负责定位项目、选择新建 / 继续哪支视频并进入 Production；不维护第二份流程状态。
- `video-init`：只建立最小必要目录与文件骨架，不询问或决定创意内容。
- `video-production`：当前单支视频唯一流程负责人，恢复事实、识别当前缺口、推进所有可做事项并维护简短当前摘要。
- `video-director`：处理整支视频的表达目标、叙事处理、表演方向、整体视觉 / 摄影 /声音策略和高层设计要求；可以提出具体镜头，但不维护另一套 Shot List 或剧情正文。
- `video-script`：维护正式剧情、动作、对白和旁白内容；导演方法发现的正式剧情修改直接写回这一唯一正文，不做形式性交接。
- `video-visual-design`：统一处理人物、地点、道具 / 虚构机械、整体视觉，以及长期参考图需要的生图 Prompt 与参考规划；设计约束、Prompt 和已确认参考图保持不同语义，不自动互相覆盖。
- `video-storyboard`：维护为什么切这一镜、展示什么、动作如何衔接、预计持续多久和计划连续性，并负责 Shot List 的正式记录。
- `video-cinematography`：与 Storyboard 共同完善同一 Shot，负责从哪里看、怎样构图 / 运动、透视 / 焦点以及镜头级灯光；不单独维护第二份镜头表。
- `video-audio`：维护可复用声音身份与当前视频的声音设计方法；最终采用音频由消费它的音频 / 剪辑记录固定。
- `video-generation`：把当前目标、Prompt、实际参考资产和必要设置编译为 Generation / Input Version 与自包含 outbound pack；具体模型能力按当前官方资料即时核验，不建立供应商 Adapter 产品层。
- `video-review`：检查资产 / Take 是否符合需求、画面声音是否合格、问题发生在哪里以及应返修哪一层；不拥有最终 selected 状态。
- `video-editing`：组织最终采用素材的剪辑、合成、全片声音、字幕 / 图文与交付 QC。
- `video-advertising`：只在真实品牌 / 产品项目中按需提供事实与广告边界。

因此不再把 `video-brief`、`video-materials`、角色 / 环境 / 道具分别拆成必经 Skill，不再单独建立 `video-continuity`，也不再维护 Runway / Veo / Seedance 模型 Adapter 系列。

## Production 决策循环

Production 不假设“先把所有图做完，再一次性生成所有视频”。它根据当前真实缺口循环推进：

1. 已有合适参考资产时，直接基于实际采用版本写视频 Prompt 并准备视频 Generation；
2. 缺少参考图时，先准备图片 Generation，等待用户外部生成并返回，Review 后再依据真实图片完成或调整依赖它的视频 Prompt；
3. 参考图不满意时继续修 Prompt / 重新生成，必要时使用已有图片作为新的生成输入，直到形成可用资产版本；
4. 视频返回暴露问题时，判断根因属于视频 Prompt、参考资产、动作 / Shot 设计还是模型能力，只回修相关层；
5. 长片 / 系列中不同 G 可以同时处于补图、待人工生成、返回待审、视频生成或剪辑状态，互不依赖的工作继续推进。

## 为什么这样做

主要使用场景是单 Agent 为用户连续推进 AI 视频，而人工外部生成只是明确的输入 / 返回暂停点。把现实剧组岗位机械映射成独立流程和文件，会产生无意义的“交回另一个 Skill”、重复正文、相互竞争的状态和过早 Gate；反过来只保留专业方法，可以让 Agent 在同一上下文中直接修正正式产物，并持续推进所有当前已经具备输入的工作。

## Consequences

Production 不使用全局固定 Stage。某个 Generation 可能在补参考图，另一个已经可打视频包，第三个已经返回待审，前半片同时可以进入粗剪；只暂停真正依赖人工输入的分支。生图和视频生成可以多轮交替，视频返回暴露问题时允许回到 Prompt、参考图、动作或设计层局部修正，而不是重跑整条流程。

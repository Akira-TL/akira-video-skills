# 视觉设计文件模板

这些模板用于把已确认方向写成长期视觉设计。只写当前对象真正需要稳定的内容，不为了模板填空。

## 1. VISUAL_DIRECTION.md

只有整片确实需要统一视觉语言时创建。

```markdown
# Visual Direction

现实程度：
<写实 / 动画 / 定格 / 纸偶 / 3D / 混合>

主要材质语言：
- ...

色彩：
- 主色：
- 辅助色：
- 重点色：
- 饱和度 / 对比关系：

光线：
- 主光方向：
- 软硬：
- 冷暖：
- 对比度：

构图倾向：
<留白 / 密度 / 主体位置 / 常见景别>

摄影倾向：
<稳定 / 手持 / 推拉摇移 / 焦段 / 景深等>

动作节奏：
<整体运动感>

允许的特效：
- ...

禁止项：
- ...

多个视觉世界：
→ 见对应世界规则（适用时）
```

## 2. CHR01_design.md

回答“这个角色视觉上是谁”。

```markdown
# CHR01 — <角色名>

来源：
<上游人物 / 用户说明 / 新设计>

设计目标：
<第一眼让观众读出什么>

整体轮廓：
<身高感、身体比例、服装外轮廓>

面部：
<脸型、年龄感、稳定识别点>

发型：
<结构、长度、刘海 / 扎发等>

身体比例：
<必要时>

基础服装：
- 剪裁：
- 层级：
- 材质：
- 主色 / 辅助色：
- 配件与固定位置：

跨镜头必须保持：
- ...

允许变化：
- costume-a / costume-b
- wet / damaged 等（真实需要时）

禁止漂移：
- ...

整体视觉方向：
→ `video/materials/VISUAL_DIRECTION.md`（存在时）

后续长期素材：
<由 video-materials 按真实需求决定 identity / four-view / costume / expression 等>
```

不写：

- 某一个镜头动作；
- 当前摄影机；
- 当前对白；
- 每个表情都可能长什么样。

## 3. LOC01_design.md

回答“这个地点作为长期空间是什么”。

```markdown
# LOC01 — <地点名>

来源：
<上游世界观 / 用户说明 / 新设计>

叙事用途：
<为什么这个地点会重复使用>

空间尺度：
<大体尺度和开放 / 封闭感>

空间骨架：
- 门：
- 窗：
- 主要通道：
- 主要家具 / 建筑 / 地形：
- 人物活动区：

视觉锚点：
- ...

材质：
- 墙 / 地面 / 天花或天空：
- 主要家具 / 建筑材料：

色彩：
- 主色：
- 辅助色：
- 重点色：

基础光线：
- 主光来源：
- 主光方向：
- 时间感：
- 冷暖 / 对比：

跨镜头必须保持：
- 门窗位置
- 主要家具关系
- 视觉锚点
- 空间比例

允许状态：
- day / night / rain 等（真实需要时）

禁止漂移：
- ...

整体视觉方向：
→ `video/materials/VISUAL_DIRECTION.md`（存在时）
```

不写：

- 某一个镜头的摄影机位置；
- 一次性爆炸 / 烟雾；
- 临时散落物；
- 当前角色站位。

## 4. PROP01_design.md（按需）

只有虚构道具 / 陌生装置真的需要长期结构设计时创建。

```markdown
# PROP01 — <名称>

用途：
<剧情 / 操作功能>

结构：
- 固定部件：
- 活动部件：
- 连接关系：

材质 / 颜色：
- ...

尺度 / 比例：
<与人物 / 场景关系>

状态：
- closed / opened / damaged 等

跨镜头必须保持：
- ...

机制：
→ 需要时引用 SPACE-MECHANISM.md 中的规则
```

真实品牌产品不使用这个模板自由重设计结构；它们由官方产品事实和官方素材约束。

## 5. 已确认方向才写正式设计

用户仍在比较 A / B / C 视觉方向时，候选可以先存在讨论或临时变体里。

正式 `CHRxx_design.md / LOCxx_design.md` 表示当前已选设计，不把多个互斥方案混在同一个文件里。

## 6. 设计更新

普通改动直接更新当前正式文件，由 Git 保存历史。

只有当前确实同时比较两套设计时才临时使用 `*_variant-a.md / *_variant-b.md`；选定后合并回正式文件并清理变体。

## 完成标准

设计文件足够让不同生成批次得到同一个角色 / 地点，同时不塞入只属于脚本、镜头或生成模型的内容。

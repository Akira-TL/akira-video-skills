# Video Script

本 Skill 只拥有 `video/script/` 中的视频化制作定义。上游小说、世界观、章节、完整人物档案、客户资料或其他来源继续归原 owning source；这里只保存当前视频为了表演、场景和镜头制作做出的转换与选择。

## 1. 读取上游来源与 VIDEO.md

先读取 `VIDEO.md` 和用户指定的上游来源。只提取当前视频真正需要的事实、人物关系、情节、场景、产品或限制；保留 pointer，不把完整上游内容复制到视频脚本层。

若来源之间存在冲突或关键事实缺失，先明确缺口；不要为了让视频脚本完整而自行补造上游事实。

## 2. 建立最小视频脚本层

只创建当前项目需要的文件：

- `SCRIPT.md`：当前视频的故事、结构、场次、动作和对白；
- `CHARACTERS.md`：当前视频中角色的表演、造型、对白和声音要求；
- `SCENES.md`：当前视频使用的场景、空间、世界表现和连续性重点；
- `SHOTS.md`：整片镜头总览。

简单产品镜头、无人物视频或已有完整脚本的项目可以缺少其中任意文件。不要为了模板完整创建空文件。

## 3. 剧情与人物

当前视频包含完整剧情、人物弧光、对白或喜剧包袱时，先读取 [`references/NARRATIVE.md`](references/NARRATIVE.md)。下面只保留所有剧情项目都需要的最小规则。

有剧情时优先保证因果链和人物行为成立，再追求视觉奇观：

- 事件由既有条件、人物选择或前一事件推动；
- 角色只基于当前已知信息行动和说话；
- 重要转折来自人物选择或已经建立的规则；
- 结尾需要回收的动作、信息或视觉元素应在前文真实建立；
- 产品或道具不能凭空解决此前没有出现的问题。

人物定义不只写性格标签。当前视频真正需要时记录目标、担忧、典型行动方式、紧张时的反应、对白节奏、声音特征、允许的情绪范围和本片变化。

## 4. 对白

对白服务角色当下行为，不负责替作者解释世界观。优先让上一句、上一动作或新信息自然引出下一句；能用动作表达的信息不要重复用对白说明。

完成对白后按连续时间顺序快速复核整段对话，检查突然换话题、重复解释、情绪无过渡、所有角色同一种句式等问题。自然对白不等于强行加入网络俚语。

## 5. 场景与镜头总览

`SCENES.md` 只记录当前视频需要的空间、视觉和世界规则。复杂机械、陌生装置或关键空间关系可以把详细说明放到对应复用素材旁的说明文件，不把所有低频规则堆进 `SCENES.md`。

`SHOTS.md` 用于从头到尾快速阅读整片镜头安排。每条至少包含 Shot ID、目标时长、画面/动作和镜头目的；详细生产要求交给 `video-shot` 的 `SHOT.md`。

长项目只有在现有镜头表已经难以阅读时才增加章节或更高一级组织，不预设电影级层级。

## 完成标准

视频脚本层足以让下一步明确知道：这支视频讲什么、当前角色如何表演、场景怎样呈现、需要哪些镜头；同时没有把上游来源复制成第二份事实库。

# 镜头预演与分镜

预演 / 分镜用于在昂贵视频生成前解决构图、走位、空间和剪辑关系。它是按需工具，不是每个镜头必须多做一张图。

## 1. 什么时候值得做

以下情况优先考虑预演：

- 多角色走位复杂；
- 人物与产品 / 机械有精确交互；
- 摄影机路径复杂；
- 相邻镜头空间连续性容易出错；
- 首帧 / 尾帧需要明确控制；
- 一个场次包含多个镜头，先看整体剪辑关系更省生成成本；
- 转场依赖动作、形状、颜色或构图匹配。

简单固定机位、单主体、动作明确的镜头可以直接进入生成，不为了流程完整强制做分镜。

## 2. 预演解决什么

优先解决：

- 画面里谁在哪里；
- 主体朝向；
- 摄影机位置和观察方向；
- 主要动作起点 / 终点；
- 产品 / 道具怎样进入画面；
- 相邻镜头从哪里切；
- 哪些空间关系必须持续。

预演不是最终美术图，不要求材质、皮肤、光效全部精修。

## 3. 存放位置

只服务一个镜头：放对应镜头目录，例如：

`storyboard.png`
`start-frame.png`
`end-frame.png`
`keyframe-01.png`

整片 / 一个场次的总览分镜确实有长期价值时，可以直接在当前 `Vxxx/` 或对应 `scenes/` 旁保存人类可读 `storyboard.png`；一次性节奏验证继续放 `.tmp/`，不需要额外创建 storyboard 目录。

## 4. 分镜不等于身份参考

粗分镜、草图和低质量预演图通常只负责：

- 构图；
- 站位；
- 动作；
- 摄影；
- 剪辑关系。

除非它本身就是已经验收的角色 / 场景参考，否则不要把分镜图同时当人物脸、服装或产品结构的身份来源。

生成包里如果同时包含身份图和分镜图，要明确写：

- 身份图负责人物身份；
- 分镜图只负责构图 / 动作。

## 5. 首帧、尾帧与关键帧

首帧 / 尾帧 / 关键帧不是新的创意来源，而是从当前 `SHOT.md` 派生出来的视觉控制点。

### 首帧

首帧必须来自：

- Continuity In；
- 当前已验收人物 / 场景 / 产品参考；
- `SHOT.md` 的起始构图与动作起点。

不能为了“首帧更漂亮”擅自：

- 换人物发型 / 服装；
- 改产品结构；
- 改地点布局；
- 改手持物；
- 把上一镜还没发生的动作提前画进去。

### 尾帧

尾帧表达**计划的** Continuity Out：

- 角色希望停在哪里；
- 道具 / 产品希望处于什么状态；
- 动作希望完成到哪一步；
- 摄影机希望结束在什么构图。

尾帧只是计划出口，不是已发生事实；真实视频回来后仍以采用结果的实际出口为下一镜依据。

### 中间关键帧

只有复杂镜头确实需要额外控制时才增加 `keyframe-01.png` 等中间关键帧，例如：

- 人物必须经过特定姿势；
- 产品操作有明确中间状态；
- 机械结构必须在某一时刻打开 / 闭合；
- 转场依赖一个具体形状 / 遮挡；
- 长镜头里存在一个模型容易跳过的关键动作。

关键帧数量越多不一定越稳定。只保留真正会减少歧义的控制点。

### 关键帧之间必须同一身份 / 空间

所有关键帧都继承同一：

- 人物身份；
- 服装 / 当前状态；
- 产品 / 道具结构；
- 场景空间；
- 世界规则。

如果关键帧之间已经互相冲突，模型不可能替项目自动决定哪一张才是正确事实。

### 派生顺序

推荐：

`SHOT.md`
→ 读取长期人物 / 场景 / 产品参考
→ 生成首帧 / 尾帧 / 必要关键帧提示词
→ 用户外部生图
→ `video-review` 验收关键帧
→ 合格后再作为视频生成输入。

关键帧图没有通过身份 / 结构 / 空间检查前，不继续把它当视频参考。

### 视频提示词

当前模型支持首帧 / 尾帧 / 关键帧控制时，最终视频提示词主要描述：

- 两个控制点之间如何运动；
- 摄影机怎样移动；
- 动作和声音怎样发生；
- 哪些状态必须保持。

不要在视频提示词里重新设计与关键帧相矛盾的静态画面。

## 6. 剪辑余量

如果镜头不是必须一开始就处于高速动作中，尽量给主要动作前后留可剪的稳定时刻：

- 动作前短暂建立；
- 动作完成后的反应 / 定格；
- 明确的结束姿势。

需要动作剪辑时，则明确前一镜和后一镜各自承担动作哪一部分，不让两个镜头都从完整动作头演到尾。

## 7. 动态分镜（Animatic）

当一个视频有较多镜头、对白、音乐节奏或严格总时长，而且直接生成全部视频成本较高时，可以先做轻量动态分镜（Animatic）。

最小 Animatic 可以只包含：

- 分镜图 / 首帧 / 简单占位图；
- 按目标时长排列的镜头；
- 临时对白 / 旁白（需要时）；
- 临时音乐 / 节拍（需要时）。

它主要验证：

- 镜头顺序是否能理解；
- 总时长是否合理；
- 对白是否放得下；
- 反应是否太短 / 太长；
- 产品是否有足够可读时间；
- 转折 / 包袱 / 片尾是否有空间；
- 哪些镜头其实重复或缺失。

Animatic 不是最终成片，也不需要把每张图做成高质量概念画。

### 存放

如果只是一次性节奏验证，可以放 `.tmp/` 并在确认后删除。

如果它是当前 V 长期有用的制作基准，可以直接放 `Vxxx/animatic.mp4` 或与对应场景共置；不要为此新建一级 preproduction / storyboard 目录。

### 发现问题时

优先修改正式来源：

- 故事 / 对白问题 → `video-script`；
- 镜头数量 / 作用问题 → 当前唯一 Shot 表 / `video-storyboard`；
- 总时长问题 → `DURATION-BUDGET.md` 对应规划；
- 产品可读性问题 → 广告 / 镜头设计。

不要先把高成本视频全生成，再用剪辑强救一个 Animatic 已经暴露的结构问题。

## 8. 预演审查

进入正式视频生成前检查：

- 空间关系是否自洽；
- 角色和产品是否能看清；
- 摄影机是否有合理位置；
- 动作是否能在目标时长完成；
- 相邻镜头是否有自然切点；
- 预演是否与长期角色 / 场景设计冲突。

## 完成标准

预演只解决正式生成前最昂贵的未知问题；它不会额外制造一套角色身份、场景事实或复杂目录。

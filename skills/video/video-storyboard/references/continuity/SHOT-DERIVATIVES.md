# 镜头派生与身份边界

用于区分“同一个镜头的后期变体”和“真正的新镜头”。

## 1. Shot 身份由剪辑语义决定

以下通常仍然是同一个 Shot：

- 裁掉头尾；
- 轻微变速；
- 稳定画面；
- 调色；
- 加字幕 / Logo；
- 横版安全裁成竖版；
- 替换音频；
- 简单遮罩 / 合成；
- 轻微重新构图。

这些属于后期派生，不新建 Shot ID。

## 2. 什么时候是新 Shot

以下情况通常应当创建新的 Shot：

- 摄影机视点真正改变；
- 剪切后形成独立的新镜头语义；
- 同一动作被拆成两个不同观察点；
- 新增反应镜头；
- 产品需要独立特写；
- 一个原生成视频里实际包含两个硬切镜头。

如果最终时间线上观众会把它理解为“切到另一个镜头”，长期项目也应当能用独立 Shot 表达。

## 3. 同一 Shot 的多画幅

同一个镜头为了 16:9 / 9:16 重新构图但剧情功能、动作结果和主体身份都相同，可以继续属于同一个 Shot。

只有两个版本已经在摄影、动作、内容上产生不同镜头语义时才拆成不同 Shot。

## 4. 同一请求生成多个内部镜头

视频模型一次请求可能生成多个硬切。

如果这些内部镜头都被最终采用：

1. 审片先判断每一段是否真的满足对应镜头目的；
2. 进入正式项目时按最终镜头语义拆到各自 Shot；
3. 原始多镜头返回文件保留在对应 `video/batches/Bxxx/returns/<task>/` 执行快照中，同时正式拆分结果进入原 Generation；
4. 不因为“它是一次 API 请求”就把多个剪辑镜头永久当成一个 Shot。

## 5. 后期派生文件

后期产生的：

- 裁切版；
- 稳定版；
- 调色版；
- 合成版；
- 替换声音版；

如果只是剪辑工程内部可重建内容，优先留在后期工程 / 缓存，不复制回镜头目录。

只有需要作为独立可交付中间件、跨软件复用或防止工程丢失时，才在当前 `Vxxx/edit/` 保存明确用途的派生媒体。

## 6. 原始生成结果不被后期覆盖

镜头目录里的 `takeNN.mp4` 表示外部生成返回的原始结果。

后期修复后的片段不要覆盖原 `takeNN.mp4`，否则无法判断 AI 原始输出和后期修复各做了什么。

时间线可以直接引用原文件 + 后期效果；必须烘焙时，烘焙文件放当前 `Vxxx/edit/` 并用用途命名。

## 完成标准

Shot ID 表示剪辑语义，而不是文件版本；生成原片、后期派生和最终成片不会互相覆盖。

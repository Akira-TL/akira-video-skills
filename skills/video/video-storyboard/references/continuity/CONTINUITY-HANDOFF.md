# 镜头连续性交接

本文件用于把相邻镜头的连续性写清，同时保持项目轻量；不建立全局状态数据库。

## 1. 先判断是否存在连续性依赖

一个镜头如果必须继承前一镜的实际可见结果，就写明依赖来源，例如：

```text
连续性依赖：SC01_SH010 当前采用结果
```

如果镜头只依赖长期角色 / 场景设计，不依赖前一个具体镜头的实际出口，可以写：

```text
连续性依赖：无（可独立生成）
```

这不是强制字段；只有依赖会影响生成顺序时才需要明确写。

## 2. 可以并行生成的镜头

通常可以并行：

- 不同场次、互不依赖的建立镜头；
- 使用同一已验收角色 / 场景参考，但不继承前一镜具体姿势 / 道具状态；
- 独立产品特写；
- 蒙太奇中彼此不共享连续动作的镜头；
- 只依赖同一长期状态基准的镜头。

这些镜头可以放进同一个 `Bxxx` 生成批次，只要各自输入都已齐全。

## 3. 必须等前一镜结果的镜头

以下情况优先串行：

- 动作从前一镜继续；
- 手里拿着什么必须一致；
- 人物确切站位 / 朝向必须继承；
- 物品损坏、液位、开合等状态由前一镜决定；
- 首帧需要前一镜真实尾帧；
- 前一镜可能产生可接受偏差，而下一镜必须据此调整。

不要在前一镜还没有采用结果时，用“计划出口”假装它已经发生。

## 4. 方向与位置的写法

连续性同时涉及**世界空间**、**画面方向**和**角色自身左右**时，必须明确是哪一种，避免“左边”这种模糊表达。

推荐写法：

- 世界空间：`LOC01 北侧门边`、`桌子东侧`；
- 画面方向：`画面左侧`、`向画面右侧移动`；
- 角色自身：`CHR01 右手握 PROP01`、`CHR01 左肩朝向门口`；
- 面向目标：`面向 CHR02`、`看向产品`；
- 摄影关系：只有真的影响下一镜时才写，例如 `摄影机仍在动作轴南侧`。

不要用：

- `左边`；
- `另一边`；
- `还是那个位置`；
- `跟上一镜一样`；

来替代需要生成模型或下一位 Agent 真正理解的空间关系。

角色自身左右不能因为反打 / 镜像变成另一只手。`CHR01 右手` 永远指角色自己的右手，`画面右侧`才是观众看到的屏幕方向。

## 5. Continuity In

只记录下一镜生成真正需要继承的可见内容，例如：

- CHR01：`LOC01 北侧门边 / 画面左侧 / 右手握 PROP01 / 面向画面右侧`；
- PROP01：`opened`；
- PROD01：`正面朝镜头，指示灯已亮`；
- LOC01：`主光仍从世界空间东侧进入`；
- 运动：`CHR01 继续向画面右侧移动`。

不把整个人物设计、场景设计、产品事实重复抄进 Continuity In。

### 最小状态块

复杂连续性可以在 `SHOT.md` 使用：

```markdown
## 连续性依赖
SC01_SH010 当前采用结果

## Continuity In
人物：
- CHR01：LOC01 北侧门边；画面左；面向画面右；右手握 PROP01

物体 / 产品：
- PROP01：opened
- PROD01：正面朝镜头；指示灯亮

场景：
- LOC01：主光从东侧进入

运动：
- CHR01 继续向画面右侧移动
```

没有复杂状态时不强制写这个完整块，一行能说清就保持一行。

## 6. 状态词保持稳定

同一个对象跨镜头尽量使用一致状态词，例如：

- `closed → opened`；
- `dry → damp → wet`；
- `intact → cracked → broken`；
- `full → half → empty`。

不要上一镜写“半湿”、下一镜写“有点潮”、再下一镜写“略微湿润”却没有说明它们是否是同一状态。

只有剧情真实改变状态时才推进；逆转状态必须有明确原因。

## 7. 计划出口

`SHOT.md` 在生成前可以写计划的 Continuity Out，表示镜头设计希望留下什么。

计划出口用于：

- 检查镜头是否有明确结束状态；
- 设计下一镜；
- 生成首尾帧（适用时）。

计划出口不是已发生事实。

## 8. 实际出口

镜头采用结果确定后，在“当前采用”记录中写实际可见出口。

下一镜如果依赖此镜头，优先继承实际出口，而不是计划出口。

如果计划和实际差异不影响剧情 / 身份 / 产品 / 结构，可以接受偏差并调整下一镜。

如果实际出口违反硬性约束，则不能为了连续性方便把错误升级成正式状态。

## 9. 前一镜更换采用结果

如果某镜头后来改用另一个生成结果：

1. 比较新的实际出口和旧的实际出口；
2. 找出明确依赖该出口的下游镜头；
3. 如果可见状态没有影响下游，记录无需重做；
4. 如果站位、朝向、手持物、产品状态、光线或动作方向改变，重新审查下游镜头；
5. 只有真的无法衔接时才重生成下游，不机械全部推倒重来。

## 10. 非相邻依赖

一个镜头也可能依赖更早的状态，而不是时间线上紧邻上一镜。

例如蒙太奇结束后回到同一房间，仍需要继承某个较早镜头已经建立的道具状态。

这时直接在 `SHOT.md` 写明依赖来源，不用创建全局状态对象。

## 11. 连续性与长期状态

以下内容仍由长期设计 / 素材负责：

- 角色基础身份；
- 场景空间；
- 产品结构；
- 角色基础声音。

镜头连续性只负责“当前这一刻变成什么样”。

## 12. 打包顺序

`video-generation` 生成包时：

- 可独立镜头可以同批；
- 依赖前一镜实际出口的镜头等前一镜审片后再打包；
- 如果依赖只涉及一个可从长期设计确定的固定状态，不必无意义等待。

## 完成标准

每个真正需要串行的镜头都有明确依赖来源；可以并行的镜头不会被无意义阻塞；计划出口和实际出口不会混成一个状态。

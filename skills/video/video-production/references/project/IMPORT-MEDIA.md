# 已有图片 / 视频 / 音频接管

当用户直接提供现成媒体，而不是从当前视频 Skill 流程生成时使用。

原则：先判断媒体在当前项目里承担什么职责，再放到对应归属位置；不要为了“流程完整”强制重新生成。

## 1. 先判断用途

用户提供的媒体可能是：

- 长期人物 / 场景 / 产品 / 道具参考；
- 某个镜头专属素材；
- 已经生成好的镜头视频；
- 真人实拍素材；
- 摄影 / 动作 / 风格参考；
- 角色声音参考；
- 粗剪 / 参考成片；
- 正式后期工程或最终成片。

同一个文件只按当前主要用途归档；不要为了分类复制到多个正式目录。

## 2. 长期复用参考

多个视频会持续引用时，进入 `video/shared/` 对应类别；只在当前 V 多个 Shot 复用时进入 `Vxxx/materials/`。

例如：

- 跨视频人物身份图 → `video/shared/characters/`；
- 跨视频地点 / 空间参考 → `video/shared/locations/`；
- 跨视频官方产品图 → `video/shared/products/`；
- 跨视频动作 / 摄影参考 → `video/shared/references/`；只服务当前 V 时放 `Vxxx/materials/`。
- 跨视频角色声音参考 → `video/shared/voices/`；只属于当前 V 的声音参考 → `Vxxx/materials/voices/`。

导入后先检查与正式设计 / 产品事实是否一致；不因为“用户有这张图”就自动覆盖已经确认的设计。

## 3. 单镜头现成素材

只服务一个镜头的图片、声音或视频放对应镜头目录。

### 用户提供的原始视频

如果它是实拍 / 外部来源，不是本项目 AI 生成结果，优先使用清楚用途名，例如：

`source.mp4`
`source-a.mp4`

不要把它误命名成 `take01.mp4`。

### 已经是本项目某镜头的 AI 生成结果

如果可以明确确认它属于当前镜头的一次生成结果，再按该镜头下一个未使用的 `takeNN.mp4` 归档。

## 4. 摄影 / 动作参考视频

只用于参考摄影、动作或节奏的视频，不自动承担：

- 人物身份；
- 服装；
- 场景；
- 产品结构。

归档 / 打包时明确写它负责什么，避免模型把参考视频中的演员、背景等一起迁移。

## 5. 粗剪 / 参考成片

用户提供一支已有粗剪：

- 如果它是当前 V 后期工作的基准，可放 `Vxxx/edit/` 并使用清楚用途名，例如 `reference-cut.mp4`；
- 如果它是跨视频风格参考，可放 `video/shared/references/`；只服务当前 V 时放 `Vxxx/materials/`；
- 不把一支参考成片拆成大量正式镜头，除非当前任务真的要复用其中素材。

## 6. 一个视频里包含多个镜头

用户提供或模型返回的视频如果包含多个明显硬切，并且这些片段要进入当前正式时间线：

1. 先完整审片；
2. 确定哪些内部段落对应当前哪些 Shot；
3. 需要独立剪辑时，把采用段落拆成对应镜头媒体；
4. 原始多镜头视频在拆分 / 归档完成前保留；
5. 不因为原文件只有一个，就在项目里永久把多个镜头当成一个 Shot。

如果整段本来就作为一个蒙太奇 / 合成段整体使用，也可以保持一个媒体文件，前提是项目长期镜头语义仍然清楚。

## 7. 导入前不要先改名到失去来源

用户刚提供文件时，先确认内容和用途，再整理项目命名。

如果原文件名包含重要来源 / 版本信息，可以在正式说明中保留 pointer；不要为了“整齐”先批量重命名到以后不知道哪个是哪个。

## 8. 来源与授权

用户提供 / 第三方现成素材仍需记录已知来源和使用边界；当前制作需要详细来源判断时按需加载 `video-visual-design` 的素材来源规则，不在 Router 复制第二套规范。

## 9. 不强制补不存在的中间件

如果用户已经有可靠人物身份图，就不需要为了流程再生成一张身份图。

如果用户已有可用视频镜头，就可以直接审片 / 进入后期；只有现有素材不足以支撑当前连续性或质量时才补设计 / 参考。

## 完成标准

已有媒体进入当前视频项目后归属清楚、用途明确、不会被误当成另一类资产；已有可用成果被直接复用，而不是为了遵守模板重新生产一次。

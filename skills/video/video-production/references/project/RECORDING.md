# 制作记录与持久化边界

目标是让下一个 Agent 不靠聊天历史也能恢复制作，同时避免项目变成生成日志。

## 1. 正文和事实只维护一处

- 当前视频剧情：`Vxxx/VIDEO.md` 或已拆出的 `scenes/SCxx.md`；
- 资产设计 / 版本来源 / 当前默认：对应 shared 或 V-local 资产记录；
- 正式 Generation 输入 / 输出：对应 G 的 `GENERATION.md`、Prompt I、参考版本和 Take；
- Shot 叙事意图：唯一 Shot 表或独立 Shot 记录；
- 正式剪辑建立后的视频最终实际采用：剪辑记录；
- 外部生成批次：`video/batches/Bxxx/` 执行快照；一个批次可包含多个 G/I，Receive 后继续保留。

同一 Prompt、对白、最终采用表不要在多个地方同步维护。

## 2. VIDEO.md 当前摘要

适合记录：当前目标 / 限制、当前阻塞、待用户操作的包、正在推进的主要事项、下一步和导航。

不适合记录：所有 Prompt 版本、每个 Take、每次模型参数、已经失效的历史决定、完整生成日志。

## 3. 资产版本

文本设计由 Git 保存历史；若某 G 需要追溯当时设计，记录真正包含该内容的 Git revision。正式投入生产的二进制参考从 `v01` 起不覆盖，新版本保留来源；更新当前默认不会修改历史 V / G 已固定引用。

## 4. Generation

G/I/Take 保存生成目标、真实正式输入、返回候选和 Review 结论。Prompt 正文只存在对应 I。Generation 不维护 selected take。

用户在外部修改 Prompt、参考或关键设置时，若结果需要保留，先把真实输入正式化为新的 I，并用新的 B 执行；不要在已 build 的批次里临时改字后继续挂回旧 I。

## 5. Shot 与剪辑

正式剪辑时间线建立前，唯一 Shot 表可记录计划 / 候选采用来源。正式时间线建立后，最终用了哪条 Take、哪段时间、是否复用 / 拼接只由剪辑记录维护；Shot 不再同步第二份最终采用结果。

## 6. Blocker 必须真实

真实 Blocker 包括：缺用户必须决定的高影响分叉、缺必要正式素材 / 授权、某分支依赖尚未返回的外部生成、关键事实冲突。Agent 普通待办不是 Blocker。

## 7. 会话结束前

检查：重要决定是否已经进入唯一正式归属；`VIDEO.md` 当前摘要是否准确；当前等待的 `Bxxx` 是否清楚；Receive 是否把结果放回原 G；正式剪辑存在时采用关系是否只在剪辑记录。

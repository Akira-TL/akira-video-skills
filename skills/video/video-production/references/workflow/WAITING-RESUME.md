# 外部生成等待与恢复

用户外部生成是正常人工往返点，只阻塞依赖它的分支。

## 1. 交付前

确认当前 `video/batches/Bxxx/` 与同目录 `Bxxx.tar.gz` 实际存在且自包含：本批 task、Prompt、副本参考、执行关系和返回目录都清楚。一个 B 可以包含多个互不阻塞的 G/I；同一参考只保留一份。

## 2. VIDEO.md 最短等待摘要

只写当前等待哪个 `Bxxx`、其中哪些 G/I 与返回后要做什么，以及真正受阻的下游。不要复制 Prompt / 参考清单 / 参数。

## 3. 等待期间

不编造返回、Review、实际出口或采用结果；但与该结果无关的其他 G、设计、Storyboarding 或剪辑继续推进。

## 4. 恢复

先看 `VIDEO.md` 当前摘要、正式 G/I、当前 B 的 `returns/<task>/` 和正式 Generation 目录：

- 未返回 → 保持等待，不重复建立同一次执行批次；
- 部分 / 一批返回 → Receive 已有 task 并继续其他工作；
- 返回后发现用户改输入 → 先正式化新的 I，再建立新的 B；
- Receive 中断 → 重跑，已完成 task 不重新分配 Take；
- 用户放弃 → 保留批次执行快照，是否清理由用户 / 项目存储策略决定。

批次目录与 tar.gz 保留；Receive 不承担自动清理。

## 5. 不靠画面猜归属

返回结果必须有可靠 scope / G / I 依据。平台改文件名没有关系，只要批次归属可靠；不能根据画面内容或上传顺序猜归属。Take 编号代表项目身份，不需要证明平台的第一 / 第二生成顺序。

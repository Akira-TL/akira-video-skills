# 外部生成等待与恢复

用户外部生成是正常人工往返点，只阻塞依赖它的分支。

## 1. 交付前

确认 `.tmp/V001/G003_I02/` 或 `.tmp/shared/G003_I02/` 实际存在且自包含：唯一 Prompt、真实上传文件、上传顺序、职责、必要设置和返回要求都在包内。需要 zip 时仍放同 scope `.tmp`。

## 2. VIDEO.md 最短等待摘要

只写当前等待哪个 G/I、pack 路径、返回后要做什么，以及真正受阻的下游。不要复制 Prompt / 参考清单 / 参数。

## 3. 等待期间

不编造返回、Review、实际出口或采用结果；但与该结果无关的其他 G、设计、Storyboarding 或剪辑继续推进。

## 4. 恢复

先看 `VIDEO.md` 当前摘要、正式 G/I、pack / returns 和正式 Generation 目录：

- 未返回 → 保持等待，不重复打同一 I；
- 部分 / 一批返回 → Receive 已有候选并继续其他工作；
- 返回后发现用户改输入 → 先正式化真实 I，再 Receive；
- Receive 中断 → 重跑，复用已预留 Take；
- 正式接收成功但清理失败 → 只重试清理，不再次导入；
- 用户放弃 → 确认无唯一信息后精确清旧 pack。

同一个 I 后续可以再回来新候选；上一批 pack 被清理不表示 I 被关闭。

## 5. 不靠画面猜归属

返回结果必须有可靠 scope / G / I 依据。平台改文件名没有关系，只要批次归属可靠；不能根据画面内容或上传顺序猜归属。Take 编号代表项目身份，不需要证明平台的第一 / 第二生成顺序。

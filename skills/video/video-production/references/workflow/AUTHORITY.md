# 视频制作权威来源

本文件定义不同制作层发生冲突时的优先级。它不要求建立额外状态文件，只规定“哪个文件 / 来源拥有哪类决定”。

## 1. 用户明确要求与上游事实

最高优先级是当前任务中用户明确确认的要求，以及项目已有上游权威来源，例如：

- 小说 / 章节里的角色关系与事件事实；
- 用户已经确认的创意决定；
- 客户 brief；
- 官方产品资料；
- 比赛 / 平台明确要求；
- 用户提供素材的使用限制。

视频 Skill 不能为了画面方便静默改写这些内容。

## 2. 视频脚本层

当前 `Vxxx/VIDEO.md` 或已拆出的 `Vxxx/scenes/SCxx.md` 拥有该视频的改编与叙事选择：

- 当前改编范围；
- 场景与事件顺序；
- 角色在本片中的行为；
- 对白；
- 镜头总览。

同一正文只维护一处。视频脚本可以在不违反上游事实的前提下做视频化转换；需要改变关键上游事实时必须作为明确改编决定。

## 3. 视觉 / 声音设计

`video-visual-design` 和 `video-audio` 拥有：

- 角色视觉身份；
- 场景视觉与空间规则；
- 整体视觉语言；
- 角色基础声音身份；
- 世界 / 机械的可视化规则。

它们把脚本中的功能要求转成具体制作设计，但不能改写人物关系、剧情事实或产品事实。

## 4. 复用资产

跨视频复用资产保存在 `video/shared/`；只属于当前视频、但会被多个镜头复用的资产保存在 `Vxxx/materials/`。对应资产记录拥有已确认参考版本及其来源，例如：

- 人物身份图与四视图；
- 地点参考；
- 产品官方素材；
- 角色声音参考；
- 当前默认使用的正式版本。

这些素材是设计的已验收实例，不反向拥有设计本身；正式生成 Prompt 仍只属于对应 G/I。

如果某张图和正式设计冲突，应修图 / 重生成，而不是修改设计去迎合错误图片。

## 5. 镜头定义

简单视频的唯一 Shot 表可以直接位于 `VIDEO.md` 或场景记录中；只有复杂 Shot 才建立独立 Shot 记录。唯一 Shot 记录拥有当前镜头的：

- 镜头目的；
- 摄影；
- 动作；
- 表演；
- 当前可见状态；
- 连续性入口 / 计划出口；
- 当前引用素材；
- 硬性约束。

镜头定义可以具体化上游设计，但不能改变角色身份、地点结构、产品事实或剧情核心。

## 6. 正式生成输入

图片 / 视频 Prompt 是从脚本、设计、资产与镜头定义编译出来的执行文本；正式正文只属于对应 Generation 的 Input Version。

提示词不是新的事实源。

如果 Prompt 与 Shot 记录或正式设计冲突，应修正对应 G/I，不让提示词反向覆盖上游。

## 7. 生成批次

`video/batches/Bxxx/` 只复制 / 编译本次实际外部执行所需的多个 G/I、共享参考和一份批次说明。

它的 README、task Prompt 副本、参考副本和 tar.gz 都不是长期权威来源。

如果批次里发现错误，先修改正式归属文件，建立正确 I，再使用新的 B 执行；不直接改旧 B 来覆盖历史实际输入。

## 8. 生成结果

生成结果是模型实际执行的产物，不天然拥有项目事实。

### 可以影响后续的内容

一个生成结果经过 `video-review` 正式采用后，它的**实际可见出口**可以成为依赖镜头的连续性依据，例如：

- 人物最终站位；
- 手里还拿着什么；
- 动作停在哪一步；
- 当前镜头实际光线 / 构图中的可接受偏差。

### 不能反向改写的内容

即使被生成出来，也不能自动升级为正式事实：

- 错误角色身份；
- 错误产品型号 / 结构；
- 错误剧情事实；
- 违反上游设定的世界规则；
- 模型随机新增的 Logo、文字、接口、人物关系。

这些结果应修复、重生成或重写镜头，不能用“模型已经画出来了”证明它是对的。

## 9. 后期工程

当前 `Vxxx/edit/` 拥有整片剪辑、合成、声音混合、字幕、Logo、图文和最终导出；正式时间线建立后，它也是视频最终实际采用关系的唯一来源。

后期可以：

- 改时长；
- 改剪切点；
- 做精确图文；
- 做确定性合成；
- 调整声音。

后期不能静默改写人物身份、产品事实和剧情事实。

## 10. 冲突处理顺序

发现冲突时按来源向上回查：

生成结果
→ 对应 G/I 的正式输入
→ Shot 记录
→ 资产记录与视觉 / 声音设计
→ 视频脚本
→ 用户 / 上游事实。

在第一个真正错误的归属层修复，不在下游打补丁掩盖上游错误。

## 11. 未定义细节

上游没有定义的低影响实现细节，可以由下游合理补全，例如：

- 不影响身份的细小材质；
- 不影响剧情的背景装饰；
- 当前镜头具体焦段；
- 小范围声音空间感。

但一旦这些细节会影响大量后续素材、角色身份、主要场景或品牌表达，就回到对应设计 / 用户确认层。

## 完成标准

每个制作决定有清楚归属；下游可以具体化上游，但不能反向重写上游事实；采用生成结果只让真实可见出口进入连续性，不让模型错误升级成项目事实。

# 一次性生成包模板

这些模板只用于 `.tmp/` 下的一次性包。长期事实仍来自正式项目文件。

## 1. README.md

```markdown
# 本次生成任务

## 目标

<一句话说明这批要生成什么>

## 当前输入

- 已确认：<角色 / 场景 / 产品 / 声音等>
- 尚缺失：无 / <如果有缺失则本批不应包含依赖它的下游任务>

## 建议顺序

1. <任务 1>
2. <任务 2>

## 任务与返回文件

| 任务 | 提示词文件 | 需要上传的素材 | 返回文件名 |
| --- | --- | --- | --- |
| CHR01 身份图 | CHR01.md | 无 | CHR01_identity.png |
| SC01_SH010 | SC01_SH010.md | materials/CHR01_identity.png | SC01_SH010_take03.mp4 |

## 重点人工检查

- <人物身份>
- <产品结构>
- <连续性 / 动作>

## 返回方式

生成完成后按上表文件名返回；平台强制改名时，至少保留任务对应关系。
```

README 不要求用户知道项目内部路径；包本身应足够独立执行。

## 5. 自包含原则

包内所有上传素材都复制到当前包的 `materials/`，任务文件只引用包内相对路径。

不要在交付包中要求用户打开：

- 项目根目录；
- `VIDEO.md`；
- Git 历史；
- 另一个 `.tmp/` 包；
- 绝对文件路径。

如果某段信息只有正式项目里有，打包时提取当前任务真正需要的最小摘要。

## 6. 不使用软链接作为交付素材

生成包用于离开项目工作区或压缩后交给用户，因此引用素材应复制成普通文件，不依赖指向包外的软链接。

如果来源文件本身是软链接，打包时读取真实目标并复制实际内容；不要把一个离开项目就失效的链接交给用户。

## 7. 驳回后的下一轮

如果 `video-review` 判定需要改提示词、设计、镜头或产品事实：

1. 先修改正式归属文件；
2. 由正式来源重新生成新的包内容；
3. 不只在旧 `.tmp/` 包里临时改字；
4. 旧包中的返回结果完成归属后即可删除。

这样下一轮包永远可由正式项目重新生成。

## 完成标准

用户只看当前包即可执行生成与返回，不需要知道项目内部结构；同时包被删除后，所有长期决定仍完整存在于正式项目。

# 生成拆分与迭代策略

## 1. 先解决生成依赖

下游生成任务依赖尚未确认的角色 / 场景 / 产品参考、声音身份或上一个镜头实际出口时，先完成并验收这些上游输入。

不要为了“一次性把包给用户”把尚不可执行的任务和缺失参考混进同一批次。串行 / 并行依赖以当前 Production / Shot 记录中的真实依赖为准：真正依赖前一结果实际出口的任务等待返回与 Review，其他输入齐全的 G 可以继续打包。

## 2. 默认不直接生成完整长片

优先按单个镜头生成。只有相邻镜头强依赖同一连续动作、当前模型明确支持多镜头生成，而且一次生成确实更容易保持连续性时，才把少量相邻镜头放在同一次请求中。

不要因为模型允许更长 duration，就自动把整段剧情塞进一次生成。

## 3. 一个生成请求承担清楚的变化

单个请求应能说明主要变化是什么，例如：

- 人物完成一个动作；
- 发现一个信息；
- 摄影机揭示一个空间；
- 完成一次转场；
- 产品完成一个真实操作。

同时塞入多个复杂动作、长对白、场景变化和大幅摄影变化，通常应该拆开。

## 4. 选择生成方式

根据实际控制需求和当前模型能力选择：

- Text to Video：探索或不依赖精确身份 / 起始构图；
- Image to Video：起始身份、构图或产品结构需要稳定；
- first / last frame：模型支持且需要控制明确起止状态；
- reference-based generation：模型支持且多种身份 / 场景 / 动作参考确实有用；
- video editing / extension：已有视频正确，只需要局部改动或延长。

这些是选择逻辑，不代表所有模型都支持全部模式；精确能力由模型适配器核验。

## 5. 先解决上游问题

如果同一失败在多个生成结果中持续出现，依次检查：

1. 角色 / 场景 / 产品设计是否含糊；
2. 参考素材是否互相冲突；
3. `SHOT.md` 是否要求过多动作；
4. 提示词是否表达不清；
5. 当前模型是否不适合这个任务。

不要把所有失败都归因于随机性。

## 6. 什么时候拆镜头

如果经过有针对性的提示词 / 参考调整后，仍无法稳定完成一个镜头，优先考虑：

- 减少同一镜头动作数量；
- 把前后动作拆成两个镜头；
- 把文字 / Logo / 精确排版移到后期；
- 先生成更稳定的关键参考图；
- 改用更适合该任务的生成模式。

不要无限增加提示词长度。

## 7. 探索与最终生成

当前工具提供明显更低成本 / 更快的草稿模式时，可以先用它验证动作和构图，再在方向稳定后做最终质量生成。

这只是成本策略；具体模型、价格和模式由当前官方资料决定，不写死在通用 Skill。

## 完成标准

每个生成请求规模与模型实际能力相符；反复失败会触发问题定位或拆镜头，而不是无止境重试同一个过载提示词。

# 一次性生成包

一次性生成包是给用户拿到外部 AI 平台执行的一次性派生包。它只从正式项目内容复制 / 编译，不成为长期事实源。

具体 README / 图片 / 视频 / 声音任务文件格式见 [`PACK-TEMPLATES.md`](PACK-TEMPLATES.md)。文件层操作优先调用本 Skill 自带 `scripts/generation_pack.py`：`init` 创建项目内包并确保 `.tmp/` 被忽略；`copy` 只复制项目内正式输入；`seal` 冻结即将交付的包内容；`returns` 创建返回目录；`status` 检查包内容；`zip` 生成同作用域派生压缩包；`receive` 将可靠归属于某个 scope / G / I 的所有返回候选幂等接收到正式 Generation、分配 G 内连续 Take、建立 Take → I 映射并在确认无唯一临时信息后自动清包。作用域化包使用 `.tmp/V001/G003_I02/` 或 `.tmp/shared/G003_I02/`。脚本不决定 Prompt 内容、素材职责、Review 结论或最终采用关系；`next-take`、`archive --confirm-reviewed` 与手动 `cleanup` 仅保留已有镜头归档流程兼容。

## 先按依赖分批

一个执行批次只打包当前已经具备全部输入的生成任务。

例如：

角色视觉设计
→ 人物四视图 / 身份图
→ 用户生成并返回
→ `video-review` 验收并归档长期角色图
→ 再生成依赖该角色图的视频镜头包。

如果下游镜头需要的角色图、场景图、产品图、声音参考或上一个镜头实际出口还没有确定，就先停止在上游素材包，不把不可执行的下游提示词一起塞给用户。

可以在同一个压缩包中包含多个彼此独立或输入已齐全的任务；存在真实先后依赖的任务分批交付。

所有包直接放在当前项目 ForgeRelay 工作区内的 `.tmp/`，不要写到操作系统其他临时目录。

## 1. 图片生成包

用于角色、场景、道具、产品等长期参考素材，也可以用于某个镜头专属的首帧、尾帧、分镜草图 / 关键帧生图。长期素材返回 `video/materials/`；镜头专属图片返回对应镜头。

推荐最小结构：

```text
.tmp/<pack-name>/
├── README.md
├── <object-id>.md
└── materials/        # 只有确实需要输入参考时创建
```

README 写清：

- 本次要生成什么；
- 当前所需输入是否已经齐全；
- 建议生成顺序；
- 每个对象的返回文件名；如果预计一次会生成多个候选，同时约定 `*_take01.png`、`*_take02.png`；
- 是否使用严格四视图；
- 需要人工重点检查什么。

对象提示词文件可以直接包含设计来源、当前长期提示词、四视图模板（如果使用）、参考图列表和返回文件名。

图片只返回一个确定结果时可以使用对应长期文件名；一次返回多个候选时先使用 `<长期名去扩展名>_take01.png`、`_take02.png` 等候选名，避免同名覆盖。

不要把整个项目资料复制进包。

## 2. 声音生成包

用于角色声音参考、某个镜头对白 / 音效，或整片级配乐 / 旁白草案。

推荐最小结构：

```text
.tmp/<pack-name>/
├── README.md
├── <voice-or-shot>.md
└── materials/        # 只有确实需要声音 / 角色参考时创建
```

README 写清：

- 当前要生成的是角色长期声音、镜头专属声音，还是整片级音乐 / 旁白；
- 文本 / 台词来源；
- 音色 / 情绪 / 节奏要求；
- 参考音频及其职责；
- 返回文件名和正式归档位置。

归档规则：

- 跨镜头角色声音定义 / 参考 → `video/materials/voices/`；
- 镜头专属对白 / 呼吸 / 音效 → 对应镜头目录；
- 全片音乐 / 旁白 / 主混音 → `video/edit/`。

如果一次生成多个声音候选，同样先在 `returns/` 使用 `_takeNN` 临时编号，选中后再进入长期稳定名。

## 3. 视频生成包

用于一个或一组镜头。

推荐结构：

```text
.tmp/<pack-name>/
├── README.md
├── SC01_SH010.md
├── SC01_SH020.md
└── materials/
```

每个镜头文件至少写清：

- 镜头 ID；
- 目标时长；
- 当前使用的提示词；
- 参考素材及各自职责；
- 用户需要在生成界面确认的参数；
- 硬性约束；
- 返回文件名。

生成界面设置只写当前任务真正需要用户确认的部分；seed、request ID、默认 UI 值等是否长期保留按 [`EXECUTION-PARAMETERS.md`](../prompting/EXECUTION-PARAMETERS.md) 判断，不为完整记录复制整张参数表。

返回文件名在对应镜头目录内使用 `takeNN.mp4`。打包前优先用 `generation_pack.py next-take` 查看正式 `video/shots/<shot-id>/` 目录已有生成结果并预留下一个未使用编号；命名按当前最大已用编号继续递增，不填补历史空号，也不得因为新提示词 / 新模型重新从 `take01` 开始覆盖旧结果。

如果用户需要从包外单独传回文件，为避免丢失归属，可以使用 `SC01_SH010_take01.mp4`；导回镜头后再按项目现有简洁命名整理。

## 4. 提示词来源

包里的提示词不能成为唯一版本。

长期图片提示词必须已存在于 `video/materials/`；长期镜头提示词必须已存在于对应 `video/shots/<shot-id>/`。

包里只复制当前版本，并根据具体模型适配器做必要的外部执行说明。

## 5. 参考素材

只复制最小充分参考集，并根据当前正式资产记录说明每份素材负责什么：人物身份、服装 / 状态、地点空间、产品 / 道具结构、动作、摄影、风格或声音。同一职责的参考互相冲突时先解决冲突再打包；不要为了“参考越多越稳”把无关资产全部带入。

不把完整 `video/materials/` 目录整体复制出去。

## 6. 对外交付

一次性生成包只有少量文本时可以直接给目录；包含多张参考图、多个镜头或用户明确需要单文件交付时，可以把当前 pack 压成一个 zip。

zip 仍保存在同一个项目 `.tmp/` 中，例如：

`.tmp/SC01-generation-pack.zip`

不要为了压缩包把内容复制到系统其他临时目录。zip 与 pack 都是一次性派生物。

## 7. 用户生成后导回

返回候选暂存在当前作用域包的 `returns/`：

```text
.tmp/V001/G003_I02/
└── returns/
    ├── platform-result-a.mp4
    └── platform-result-b.mp4
```

然后：

1. 先用可靠信息确认 scope / G / I；不能根据画面内容或上传顺序猜归属；
2. `receive` 把同一返回批次的所有候选正式保存为 G 内连续 `takeNN`，保留原平台文件名 / 标识作为辅助来源记录；切换 I 不重置 Take；
3. 单个媒体文件通常就是一个 Take；同一候选确实由视频、音轨、字幕等配套文件组成时，可以把一个返回子目录作为一个 Take 文件集合；
4. 所有候选正式接收后再进入 `video-review`；Generation 只记录检查结论和问题范围，不维护 selected take；
5. 图片 Take 被采用为人物 / 地点 / 道具参考时，由对应资产记录写明具体资产版本来源；视频实际采用的 Take / 时间范围在尚无正式剪辑时可记于唯一 Shot 表，建立正式剪辑时间线后以剪辑记录为最终采用源；
6. 如果用户实际改了 Prompt、参考或关键设置，先把真实输入正式保存为正确 I，再接收结果；无法确定实际输入时保留临时包待核对；
7. Receive 中途失败可以重跑，已预留 / 已保存的 Take 不重新编号；正式接收成功但清理失败只重试清理，不重新导入。

## 8. 自动清理临时包

Receive 只有在返回候选和 Take → I 映射已经正式保存，并确认包中没有尚未正式保存的唯一 Prompt、替换参考、实际设置或返回结果后，才自动删除精确对应的 `.tmp/<scope>/Gxxx_Iyy/` 与派生 zip。上一批包删除不代表该 I 被关闭；同一 I 后续仍可创建新的交付包并接收更多候选。

一次性生成包默认不进入 Git。

## 完成标准

用户打开包即可知道按什么顺序生成、每个提示词对应什么、要上传哪些素材、生成后文件叫什么；同时删除整个包不会损失任何长期项目信息。

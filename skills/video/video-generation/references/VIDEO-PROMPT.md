# 通用视频提示词编译

`SHOT.md` 是内部制作定义；最终视频模型提示词是从它编译出来的执行文本，两者不要混为同一个文件。

## 1. 先固定镜头意图

在编译提示词前确认 `SHOT.md` 已经明确：

- 这个镜头为什么存在；
- 谁 / 什么是主体；
- 发生什么动作；
- 摄影机做什么；
- 镜头从什么状态开始、结束；
- 哪些复用素材负责身份 / 场景 / 产品结构；
- 哪些是不可破坏的硬性约束。

缺失这些内容时先回 `video-shot`，不要靠提示词临时发明导演意图。

## 2. 编译顺序

通用视频提示词可以按当前镜头需要选择以下信息：

主体 / 起始状态
→ 动作
→ 摄影机
→ 环境变化
→ 表演 / 情绪
→ 秒级时序
→ 对白 / 声音（当前模型支持且镜头需要时）
→ 必要的一致性与限制。

不是所有模型都需要同样的顺序；已加载模型适配器时，以适配器为最终编译层。

## 3. 参考图已经表达的内容

图生视频时，参考图已经定义清楚的静态身份、构图、服装和场景，不要在最终提示词中无意义重复整段描述。

提示词主要写“从这张图开始，接下来发生什么”。

## 4. 时间

优先使用自然的秒级时间段或顺序词。

动作数量必须符合目标时长。一个 5 秒镜头不应同时要求角色完成多个复杂动作、长对白、完整转场和大幅摄影变化。

## 5. 硬性约束

`SHOT.md` 可以保存完整 硬性约束，但最终模型提示词只编译真正需要模型执行的约束。

能在后期确定性解决的字幕、Logo、精确排版、剪切点、音量等，不要为了“完整”塞进生成提示词。

## 6. 正向描述

优先直接描述目标画面和动作。禁止项只保留那些如果不说就高概率破坏身份、结构、空间或剧情的关键约束。

## 7. 多镜头模型

模型支持一次生成多个内部镜头时，可以在提示词中写时间线 / hard cut，但项目里的镜头语义仍由 `video-shot` 维护。

一个模型请求覆盖多个镜头时，一次性生成包 仍要让用户看得出最终每个镜头的用途和返回归属。

## 8. 迭代

生成失败先判断失败来源。修改提示词时优先一次改一个主要变量，例如：

- 动作表达；
- 摄影；
- 时间；
- 参考素材；
- 一致性约束。

不要每次把提示词变得更长。

## 完成标准

最终提示词足够让当前模型执行既定镜头，同时没有把内部项目文档、无关素材和可后期解决的要求一股脑塞进去。

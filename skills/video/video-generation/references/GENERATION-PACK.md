# 一次性生成包

一次性生成包是给用户拿到外部 AI 平台执行的一次性派生包。它只从正式项目内容复制 / 编译，不成为长期事实源。

具体 README / 图片 / 视频 / 声音任务文件格式见 [`PACK-TEMPLATES.md`](PACK-TEMPLATES.md)。

## 先按依赖分批

一个执行批次只打包当前已经具备全部输入的生成任务。

例如：

角色视觉设计
→ 人物四视图 / 身份图
→ 用户生成并返回
→ `video-review` 验收并归档长期角色图
→ 再生成依赖该角色图的视频镜头包。

如果下游镜头需要的角色图、场景图、产品图、声音参考或上一个镜头实际出口还没有确定，就先停止在上游素材包，不把不可执行的下游提示词一起塞给用户。

可以在同一个压缩包中包含多个彼此独立或输入已齐全的任务；存在真实先后依赖的任务分批交付。

所有包直接放在当前项目 ForgeRelay 工作区内的 `.tmp/`，不要写到操作系统其他临时目录。

## 1. 图片生成包

用于角色、场景、道具、产品等长期参考素材，也可以用于某个镜头专属的首帧、尾帧、分镜草图 / 关键帧生图。长期素材返回 `video/materials/`；镜头专属图片返回对应镜头。

推荐最小结构：

```text
.tmp/<pack-name>/
├── README.md
├── <object-id>.md
└── materials/        # 只有确实需要输入参考时创建
```

README 写清：

- 本次要生成什么；
- 当前所需输入是否已经齐全；
- 建议生成顺序；
- 每个对象的返回文件名；如果预计一次会生成多个候选，同时约定 `*_take01.png`、`*_take02.png`；
- 是否使用严格四视图；
- 需要人工重点检查什么。

对象提示词文件可以直接包含设计来源、当前长期提示词、四视图模板（如果使用）、参考图列表和返回文件名。

图片只返回一个确定结果时可以使用对应长期文件名；一次返回多个候选时先使用 `<长期名去扩展名>_take01.png`、`_take02.png` 等候选名，避免同名覆盖。

不要把整个项目资料复制进包。

## 2. 声音生成包

用于角色声音参考、某个镜头对白 / 音效，或整片级配乐 / 旁白草案。

推荐最小结构：

```text
.tmp/<pack-name>/
├── README.md
├── <voice-or-shot>.md
└── materials/        # 只有确实需要声音 / 角色参考时创建
```

README 写清：

- 当前要生成的是角色长期声音、镜头专属声音，还是整片级音乐 / 旁白；
- 文本 / 台词来源；
- 音色 / 情绪 / 节奏要求；
- 参考音频及其职责；
- 返回文件名和正式归档位置。

归档规则：

- 跨镜头角色声音定义 / 参考 → `video/materials/voices/`；
- 镜头专属对白 / 呼吸 / 音效 → 对应镜头目录；
- 全片音乐 / 旁白 / 主混音 → `video/edit/`。

如果一次生成多个声音候选，同样先在 `returns/` 使用 `_takeNN` 临时编号，选中后再进入长期稳定名。

## 3. 视频生成包

用于一个或一组镜头。

推荐结构：

```text
.tmp/<pack-name>/
├── README.md
├── SC01_SH010.md
├── SC01_SH020.md
└── materials/
```

每个镜头文件至少写清：

- 镜头 ID；
- 目标时长；
- 当前使用的提示词；
- 参考素材及各自职责；
- 用户需要在生成界面确认的参数；
- 硬性约束；
- 返回文件名。

返回文件名在对应镜头目录内使用 `takeNN.mp4`。打包前先查看该镜头已有生成结果，预留下一组未使用编号；不得因为新提示词 / 新模型重新从 `take01` 开始覆盖旧结果。

如果用户需要从包外单独传回文件，为避免丢失归属，可以使用 `SC01_SH010_take01.mp4`；导回镜头后再按项目现有简洁命名整理。

## 4. 提示词来源

包里的提示词不能成为唯一版本。

长期图片提示词必须已存在于 `video/materials/`；长期镜头提示词必须已存在于对应 `video/shots/<shot-id>/`。

包里只复制当前版本，并根据具体模型适配器做必要的外部执行说明。

## 5. 参考素材

只复制最小充分参考集，并按 `video-materials/references/REFERENCE-ROLES.md` 说明每份素材负责什么：人物身份、服装、场景、产品结构、动作、摄影、风格或声音。同一职责的参考互相冲突时先解决冲突再打包。

不把完整 `video/materials/` 目录整体复制出去。

## 6. 对外交付

一次性生成包只有少量文本时可以直接给目录；包含多张参考图、多个镜头或用户明确需要单文件交付时，可以把当前 pack 压成一个 zip。

zip 仍保存在同一个项目 `.tmp/` 中，例如：

`.tmp/SC01-generation-pack.zip`

不要为了压缩包把内容复制到系统其他临时目录。zip 与 pack 都是一次性派生物。

## 7. 用户生成后导回

一批返回文件需要先暂存时，放在当前 pack 内的 `returns/`，例如：

```text
.tmp/SC01-generation-pack/
└── returns/
    ├── SC01_SH010_take01.mp4
    └── SC01_SH020_take01.mp4
```

然后：

1. 根据返回文件名确定归属；文件名不规范但有明确一一对应关系时可以整理，多个返回文件无法可靠对应对象 / 镜头时停止并向用户确认，不按上传顺序猜；
2. 保留原始返回文件，先进入 `video-review`；
3. 图片有多个候选时先完成选择，只有选中的结果归档为对应长期稳定名；未选候选默认留在临时 pack 等待清理；
4. 图片长期素材归入对应 `video/materials/<category>/`；
5. 镜头视频、镜头专属图片 / 音频归入对应镜头；
6. 如果文件名不符合约定但归属明确，正式归档时整理为项目命名；
7. 更新必要的 `VIDEO.md` 当前工作。

返回文件也不能因为“暂存在 pack”就成为长期唯一副本。

## 8. 删除临时包

只有当返回结果已经进入正式项目、包里没有唯一提示词 / 唯一参考图、且没有尚未导回的生成结果时，才删除整个一次性生成包。

一次性生成包默认不进入 Git。

## 完成标准

用户打开包即可知道按什么顺序生成、每个提示词对应什么、要上传哪些素材、生成后文件叫什么；同时删除整个包不会损失任何长期项目信息。

# 视频模型适配器验收场景

本文件用于模型适配器开发、回归和从 in-progress 晋升稳定前的黑盒验收。

验收对象是“模型适配能力”，不是视频模型本身的生成质量。测试时可以不真正调用付费生成，但必须验证适配器在已知 / 未知能力、输入映射和输出契约上的行为。

## A. 精确入口与模型

给定：

- 同一模型家族存在多个入口；
- stable / preview 能力不同；
- 用户只说“用 Veo / Runway / Seedance”。

期望：

- 适配器先要求 / 推导当前真实使用入口；
- 明确精确 model / version / mode；
- 不把家族名当完整能力契约；
- 当前信息不足以选择时，返回缺失项而不是猜。

失败：

- 直接按记忆套参数；
- 把 preview 能力写成 stable；
- 把官方 API 能力套到第三方 Router。

## B. 当前能力核验

给定一个会变化的能力，例如：

- 时长；
- 分辨率；
- 首尾帧；
- 参考图数量；
- 同步声音；
- edit / extend。

期望：

- 当该能力影响当前任务时，读取最近官方资料；
- 说明当前入口 / 模型；
- `MODEL-GUIDE.md` 快照过期时不把旧值当永久事实；
- 官方未证明时 fail closed。

失败：

- “我记得这个模型支持”；
- 使用旧 preview 文档；
- 第三方博客覆盖官方文档。

## C. Image to Video

给定：

- 已验收人物 / 场景起始图；
- `SHOT.md` 已定义动作和摄影。

期望：

- 图片负责已存在的静态视觉；
- 模型提示词重点描述后续动作、摄影、环境变化；
- 不重新长篇描述人物脸 / 场景导致身份竞争；
- 当前模型特有要求只在适配层添加。

失败：

- 输入图 + 提示词同时给出互相冲突的角色 / 场景；
- 适配器重新设计服装或场景。

## D. Text to Video

给定没有输入图的简单镜头。

期望：

- 提示词包含当前模型真正需要的视觉 + 运动；
- 不机械填满长模板；
- `SHOT.md` 的镜头目的 / 动作保持不变；
- 精确参数由当前模式核验。

失败：

- 为了满足适配器模板新增剧情动作；
- 堆叠互相冲突的摄影 / 风格词。

## E. 参考素材职责

给定：

- 人物身份图；
- 服装状态图；
- 场景图；
- 动作参考视频；
- 产品官方图。

期望：

- 每份输入有明确职责；
- 上传顺序 / element ID / reference ID（模型需要时）正确；
- 动作参考不自动迁移演员身份；
- 产品图只负责产品结构；
- 不超出当前模型真实输入上限；
- 最小充分参考集，而不是全项目上传。

失败：

- 参考职责模糊；
- 多份素材竞争同一个身份；
- 用历史上限替代当前入口上限。

## F. 首帧 / 尾帧 / 关键帧

给定已验收首尾帧。

期望：

- 当前模式确认支持后才启用；
- 提示词描述控制点之间怎样变化；
- 不重新描述与控制帧冲突的静态事实；
- 尾帧仍只是计划出口，生成后由 `video-review` 记录实际出口。

失败：

- 当前入口不支持仍强行使用；
- 把计划尾帧写成已发生事实。

## G. 同步声音

给定一个包含对白的镜头。

期望：

- 当前模式明确支持声音时才编译；
- 对白文本来自 `video-script`；
- 声音身份来自 `video-audio`；
- 只加入当前镜头需要的对白 / 环境声 / 音效；
- 不为了展示模型声音能力新增台词。

当前模式不支持时：

- 明确声音交给后期 / 单独生成；
- 视频提示词不伪造“会输出同步音频”。

## H. Edit / Extend

给定当前采用 `take03.mp4`，要求延长或局部编辑。

期望：

- 当前模型 / 模式先确认支持；
- 项目语义仍遵守 `video-generation` 的 edit / extend 规则；
- 原始 `take03.mp4` 不覆盖；
- 完整新结果建议使用下一未占用 `takeNN`；
- 只返回续段时不冒充完整 take；
- 修改后要求重新完整审片。

## I. 能力不匹配

给定镜头必须使用某项当前模型没有 / 未确认的能力。

期望：

适配器返回：

- 缺少什么；
- 当前已确认可用的替代模式；
- 是否需要换入口 / 模型；
- 是否适合回后期；
- 是否必须回 `video-shot` 修改镜头。

失败：

- 静默删除镜头要求；
- 私自改剧情 / 动作；
- 假设模型支持。

## J. 模型切换

同一 `SHOT.md` 从模型 A 切模型 B。

期望：

- 镜头身份不变；
- 不复制一套 Shot；
- 创建 / 更新模型专用提示词；
- B 的字段从 B 的当前文档核验，不复制 A 的参数；
- 生成结果继续使用同一 Shot 内递增编号。

## K. 第三方入口

给定用户通过第三方聚合平台调用同名模型。

期望：

- 明确“官方模型能力”和“当前第三方入口暴露能力”不是一回事；
- 当前入口字段 / 上限缺文档时标记未知；
- 不把官方 endpoint 参数直接交给第三方 UI。

## L. 统一输出契约

无论模型，适配器最终能给 `video-generation` 提供适用项：

- 供应商 / 产品；
- 实际使用入口；
- 精确模型 / 版本；
- stable / preview；
- 任务模式；
- 当前提示词；
- 输入素材与职责；
- 用户需要确认的设置；
- 当前未支持 / 未确认能力；
- 能力核验状态。

简单模式可以省略不适用字段，但不能省略关键歧义。

## M. 不越权

给定用户镜头里存在模型不擅长的复杂动作。

期望：

- 适配器说明能力风险；
- 可以建议更合适模型 / 模式；
- 可以建议回 `video-shot` 简化；
- 不能直接把动作删掉后还宣称“同一个镜头”。

同理，适配器不能：

- 改人物外形；
- 改产品事实；
- 改对白内容；
- 改场景布局；
- 改用户确认的视觉方向。

## N. 过期快照

把 `MODEL-GUIDE.md` 的最近核验日期模拟为明显过期，并给出一个依赖动态上限的任务。

期望：

- 适配器触发重新核验；
- 不只因为仓库里有一个旧数字就继续。

对不依赖动态能力的纯提示词改写，可以继续使用稳定方法部分，不要求每次所有任务都上网查一遍。

## O. Package 边界

单独安装模型适配器 Package。

期望：

- 声明的 required dependency 足够；
- 不通过源码相对路径读取未声明 sibling Package；
- 一次性包、归档、命名仍交 `video-generation`；
- Router 没安装也不影响已明确调用的模型适配器完成自身编译职责。

## 稳定晋升判定

一个适配器准备从 in-progress 晋升稳定时：

- A–O 所有适用场景通过；
- 不适用场景说明原因；
- 最近人工核验日期更新；
- 官方来源可访问且对应当前入口；
- 依赖闭包通过 Skiloom；
- 仓库本地链接 / reference 可达性通过；
- 至少一个真实项目或独立 fixture 验证了核心模式，而不是只看文档。

如果因为外部平台不可访问，无法完成真实调用质量测试，可以标记该部分 **inconclusive**；但能力契约 / fail-closed / 输出格式这些不依赖实际生成的场景仍必须通过，不能把环境问题当成产品通过。

## 完成标准

模型适配器的正确性可以由统一场景重复验证，新模型只新增真正的模型差异；不会因为供应商不同而重新发明一套路由、项目状态、命名和生成包系统。

# 同一 Generation 的跨模型比较

只有当前制作确实需要比较不同模型时使用。模型是执行方式，不是 Shot 或 Generation 身份。

## 1. 保持同一 G 目标

比较模型时尽量保持同一个 Generation 目标、核心参考资产、动作、硬约束和相近时长。不同模型如果必须使用不同输入形式或设置，把差异写进各自正式 Input Version。

例如：

- `G003 I01` — 当前模型 A；
- `G003 I02` — 当前模型 B；

每个 I 的 Prompt、参考文件和设置独立冻结；Take 编号仍在同一 G 内连续递增。

## 2. 当前能力必须实时核验

模型的参考、时长、声音、首尾帧、编辑 / 延长等动态能力以当前官方资料为准。第三方入口只按该入口真实暴露的能力使用，不把官方 API 能力自动套到第三方 UI。

## 3. 比较真正重要的维度

按当前 G 目标比较身份 / 结构稳定、动作、摄影、声音、时间一致性、参考兼容性、速度或成本。不存在仓库级“全局最好模型”排名。

## 4. 不反写创作事实

切换模型可以改变 Prompt 编译和执行设置，不能偷偷改变人物、产品、场景、剧情或 Shot 核心目的。只有正式制作目标改变时才修改上游记录或新建 G。

## 完成标准

跨模型测试仍属于同一个明确 Generation 目标；每个 Take 都能追溯到真实 I，而项目不按供应商复制一套资产或镜头结构。

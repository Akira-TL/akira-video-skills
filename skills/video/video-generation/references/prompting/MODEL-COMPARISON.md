# 同一镜头跨模型比较

当同一个镜头需要比较 Veo、Runway、Seedance 或其他视频模型时使用。

## 1. 模型不是镜头版本

同一个镜头的：

- 镜头目的；
- 动作；
- 摄影；
- 连续性；
- 人物 / 场景 / 产品身份；
- 硬性约束；

仍然由同一份 `SHOT.md` 定义。

切换视频模型不自动创建新的 Shot ID，也不需要复制一套 `SHOT.md`。

## 2. 模型专用提示词

只有一个模型路线时继续使用：

`prompt_v01.md`

同一镜头确实同时比较多个模型时，可以并列：

`prompt_veo_v01.md`
`prompt_runway_v01.md`
`prompt_seedance_v01.md`

每份提示词从同一镜头意图编译，但可以根据模型能力调整：

- 参考输入形式；
- 时长；
- 首尾帧；
- 多模态 reference；
- 声音；
- 时间线写法；
- 摄影表达。

模型适配不能改变镜头本来要完成的剧情 / 信息任务。

## 3. 尽量控制比较变量

想比较“哪个模型更适合这个镜头”时，尽量保持：

- 同一个镜头目的；
- 同一组核心人物 / 场景 / 产品参考；
- 相近目标时长；
- 相同核心动作；
- 相同硬性约束。

如果某模型因为能力限制必须使用不同模式或时长，把差异写清，不假装完全同条件。

## 4. 生成结果编号不按模型重置

同一镜头的生成结果继续单调递增：

`take01.mp4` — Runway
`take02.mp4` — Runway
`take03.mp4` — Veo
`take04.mp4` — Seedance

不要为每个模型建立：

`runway/take01`
`veo/take01`
`seedance/take01`

这种默认子目录；它会把一个镜头拆成多个模型仓库。

## 5. 比较期间怎样记模型来源

一次性生成包 README 必须明确：

```text
SC01_SH010_take03.mp4 — Veo 3.1 / 当前使用入口 / prompt_veo_v01.md
SC01_SH010_take04.mp4 — Seedance 2.5 / 当前使用入口 / prompt_seedance_v01.md
```

如果比较完成后未采用结果仍需要长期保留，而且未来还需要知道模型来源，可以在 `SHOT.md` 增加一个非常短的“生成比较”表；没有长期分析价值时不额外维护日志。

## 6. 当前采用记录

选定结果后在 `SHOT.md` 的“当前采用”中记录：

- 生成结果；
- 对应提示词；
- 模型 / 使用入口（对复现和后续连续性有意义时）。

模型名只用于说明执行来源，不改变镜头身份。

## 7. 比较重点

根据当前镜头真正重要的维度比较，例如：

- 人物身份稳定；
- 产品结构；
- 动作；
- 摄影；
- 多角色交互；
- 声音；
- 时间线；
- 物理；
- 当前参考素材兼容性；
- 生成成本 / 速度（用户关心时）。

不维护“全局最好模型”排名。一个模型适合产品结构，不代表它在复杂多人动作上也一定最好。

## 8. 能力不匹配时直接换模型

如果当前模型明确缺少这个镜头真正需要的能力，例如：

- 无法使用必要参考；
- 不支持需要的首尾帧；
- 无法满足当前时长；
- 当前声音能力无法满足要求；

可以直接换更合适的模型 / 生成模式，不需要先在不适合的模型上大量失败。

动态能力必须由对应模型适配器或当前官方资料核验。

## 9. 不让模型差异反写镜头

为了某模型更好生成，可以改写执行提示词，但不能为了迁就模型让：

- 人物目标变化；
- 产品功能变化；
- 镜头核心动作变化；
- 关键连续性消失。

如果只有改变镜头本身才可实现，应回 `video-shot` 正式修改镜头设计，而不是把变化藏在模型专用提示词里。

## 完成标准

跨模型测试仍围绕同一个镜头意图；模型专用提示词和返回文件可追溯，但项目不会按模型复制一套镜头结构。

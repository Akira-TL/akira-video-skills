# 视频模型适配器契约

本契约定义可选视频模型适配 Skill 与 `video-generation` 的统一接口。

模型适配器只负责把已经成立的镜头 / 素材意图编译成某个**具体使用入口 + 精确模型 + 任务模式**当前可以执行的请求；它不是新的镜头设计层，也不拥有项目事实。

## 1. 必须先锁定四件事

使用任何模型专用规则前，先明确：

1. **供应商 / 产品**：例如 Runway、Google、BytePlus；
2. **实际使用入口**：例如官方网页、Vertex AI、ModelArk、第三方路由；
3. **精确模型 / 版本**：例如某个 stable model ID，而不是只说“Veo”；
4. **任务模式**：Text to Video、Image to Video、首尾帧、reference、edit、extend 等。

同一家模型在不同入口、stable / preview、不同 model ID 上的能力可能不同。

不能用“这个家族以前支持过”推断当前入口也支持。

## 2. 动态能力必须重新核验

以下信息会变化，影响当前生成时必须以官方当前资料为准：

- 输入类型；
- 图片 / 视频 / 音频参考能力；
- 参考数量与大小限制；
- 时长；
- 画幅比例；
- 分辨率；
- FPS；
- 同步声音；
- 首尾帧；
- 多镜头；
- 编辑；
- 延长；
- 输出格式；
- endpoint / model ID；
- stable / preview 状态。

适配器自己的 `references/MODEL-GUIDE.md` 可以保存最近人工核验快照，但不能把快照日期当成永久事实。

如果当前任务依赖某项精确能力，而最近核验已经可能过期，重新查看官方资料。

## 3. 官方来源优先级

模型能力优先使用：

1. 当前供应商官方 API / 模型文档；
2. 当前供应商官方产品帮助页；
3. 当前供应商官方 prompting / creation guide；
4. 当前供应商官方 release notes。

第三方博客、聚合站、旧评测和社区经验只能补充使用体验，不能覆盖当前官方能力契约。

如果官方文档之间互相不一致：

- 先区分使用入口；
- 区分 stable / preview；
- 区分模型版本；
- 明确当前仍存在的不确定性；
- 不自行合并成一个“肯定支持”的结论。

## 4. 未知能力 fail closed

当前官方资料没有明确证明某项能力时，适配器输出：

`当前入口 / 模型未确认支持 <能力>`

然后：

- 选择已经确认可用的模式；
- 或要求切换入口 / 模型；
- 或把任务交给后期 / 其他模型。

不要为了继续生成而假设支持。

## 5. 适配器输入

适配器从 `video-generation` / 项目读取的输入只包括当前任务真正需要的：

- `SHOT.md` 或当前素材生成意图；
- 已验收长期人物 / 场景 / 产品 / 道具参考；
- 当前镜头专属首帧 / 尾帧 / 关键帧；
- 当前声音要求；
- 当前硬性约束；
- 当前目标时长 / 画幅等制作需求。

适配器不能从旧聊天、旧生成包或模型历史输出重建新的项目事实。

## 6. 不拥有的内容

模型适配器不能重新决定：

- 剧情；
- 人物关系；
- 角色视觉身份；
- 场景空间；
- 产品事实；
- 镜头目的；
- 当前连续性；
- 用户已经确认的创意方向。

如果当前模型无法执行既定镜头，应返回：

- 能力缺口；
- 更合适的模型 / 模式；
- 或需要回 `video-shot` 正式修改镜头的原因。

不能把改变镜头意图偷偷藏在模型专用提示词里。

## 7. 提示词编译

适配器可以根据模型当前方法调整：

- 信息顺序；
- 摄影表达；
- reference mapping；
- timeline；
- 首尾帧表达；
- 声音写法；
- edit / extend 动作词；
- 当前必要限制。

但核心仍来自同一镜头 / 素材意图。

简单镜头不为了模型模板机械写成长提示词。

## 8. 参考素材映射

模型支持多模态参考时，每份输入必须说明职责，例如：

- 人物身份；
- 当前服装 / 状态；
- 场景空间；
- 产品结构；
- 动作；
- 摄影；
- 风格；
- 声音。

如果模型要求上传顺序 / element ID / reference ID，适配器负责编译当前入口需要的映射。

适配器不能因为某模型“参考多”就把所有项目素材都上传。

最小充分参考集仍由 `video-materials` / `video-generation` 决定。

## 9. 声音能力

模型当前模式明确支持同步声音时，适配器可以编译：

- 对白；
- 旁白（当前镜头真的需要时）；
- 环境声；
- 关键音效；
- 时间位置。

但：

- 对白文本来自 `video-script`；
- 角色声音身份来自 `video-audio`；
- 音乐 / 最终混音不因为模型能出声音就强塞进镜头生成。

没有可靠声音能力时，明确交给后期配音 / 混音，不伪装“模型会自动做好”。

## 10. 延长 / 编辑

模型支持 edit / extend 时：

- 项目语义仍遵守 `video-generation` 的延长 / V2V 编辑规则；
- 适配器只负责该模型具体输入与提示词；
- 原始 `takeNN.mp4` 不覆盖；
- 新硬切 / 新视点 / 新叙事功能仍属于新 Shot；
- 当前模型编辑可能污染人物 / 产品时必须重新完整审片。

## 11. 适配器统一输出

适配器返回给 `video-generation` 时，至少提供适用项：

```text
供应商 / 产品：
实际使用入口：
精确模型 / 版本：
stable / preview：
任务模式：

当前提示词：

输入素材：
- <文件> — <职责>
- ...

需要用户确认的执行设置：
- 时长：
- 画幅：
- 分辨率：
- 声音：
- 其他：

当前明确不支持 / 未确认能力：
- ...

官方能力核验：
- 最近核验日期：
- 本次是否重新核验：
```

不适用字段可以省略，不为了模板填空。

## 12. 返回给 generation，不自行打包

模型适配器不拥有：

- 一次性生成包目录；
- 返回文件编号；
- `.tmp/` 生命周期；
- 正式媒体归档；
- 当前采用结果。

这些继续由 `video-generation` / `video-review` 负责。

适配器只给：

- 最终执行提示词；
- 输入映射；
- 需要用户确认的模型设置；
- 已知能力限制；
- 当前能力核验结论。

## 13. stable / preview

如果供应商同时提供 stable / preview：

- 明确当前选的是哪一个；
- 不把 preview 能力写成 stable 能力；
- 不因为 preview 功能更多就默认推荐它；
- 用户 / 项目需要稳定性、长期复现或生产 API 时，把 release 状态纳入选择；
- preview 被弃用 / 升级时，更新 adapter guide，不移动旧项目事实。

## 14. 模型家族升级

出现新版本时：

- 不直接把旧版本参数复制过去；
- 重新核验官方能力；
- 重新检查 prompting guide；
- 高风险镜头按批量生成规则先小样；
- 同一 Shot 的镜头意图保持不变，模型专用提示词可以新增版本。

旧模型仍在项目中被采用时，不因为新模型发布就重写历史记录。

## 15. 第三方路由

用户通过第三方平台调用同名模型时：

- 不能假定它暴露全部官方能力；
- 先核验第三方入口实际支持的字段 / 限制；
- 如果第三方没有可靠文档，至少明确“这是该入口的未确认项”；
- 不把官方 API endpoint 参数直接套到第三方 UI。

## 16. 能力快照文档

每个适配器的 `MODEL-GUIDE.md` 至少保持：

- 最近人工核验日期；
- 当前重点模型 / 入口；
- 当前已确认能力；
- 入口差异 / 已知不确定项；
- 当前提示词方法摘要；
- 官方来源。

避免：

- 复制整篇官方文档；
- 把旧 preview 能力留成“当前支持”；
- 把第三方经验写成官方限制；
- 把能力上限写成推荐目标。

## 17. 适配器晋升稳定前

in-progress 适配器准备进入稳定目录前，至少确认：

- 遵守本契约；
- 当前主模型 / 入口已经重新核验；
- Package dependency 最小且真实；
- 典型 Text / Image / reference / audio / edit 分支（适用时）有最小回归检查；
- 不依赖项目源码相对路径去读取另一个未声明 Package；
- 用户文档已经同步；
- 默认 Router 仍不会自动安装所有模型适配器。

## 完成标准

模型适配器能把同一个正式镜头 / 素材意图可靠编译到具体入口，同时把动态能力、入口差异和未知项显式暴露；它不会重新设计作品，也不会把历史模型记忆或 preview 能力当成当前事实。

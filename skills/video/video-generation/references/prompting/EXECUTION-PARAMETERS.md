# Generation 执行参数与持久化边界

本文件区分长期制作事实与某个 Generation Input Version 的执行设置，避免供应商 UI 字段污染项目。

## 1. Shot 不拥有模型参数

Shot 保存叙事目的、动作、连续性和摄影意图；模型 / 模式 / 时长 / 画幅 / 声音开关等真正影响执行的设置属于对应 G/I。

默认不长期保存 request ID、排队状态、临时价格、网页默认值或每次点击的 UI 噪声。

## 2. I 保存真正影响执行的设置

每个正式 I 至少能说明执行当前 Prompt 所需的模型 / 入口、模式、目标时长、画幅、实际参考版本、声音等关键选项。只有当前用户需要手动确认或后续复现 / 排错有价值的字段才保存，不复制整张 UI 表单。

Prompt 正文只在该 I 的 Prompt 文件；设置可以放 `GENERATION.md` 对应 I 记录，不复制进资产或 Shot。

## 3. 动态能力实时核验

具体模型支持哪些时长、分辨率、参考数量、声音、首尾帧或 edit / extend，以当前官方资料和实际入口为准。没有可靠依据就标未确认，不建立供应商 Adapter Skill。

## 4. seed 不是身份系统

人物 / 产品一致性优先来自正式设计、已确认参考版本和可靠 reference 机制。seed 最多是执行控制；只有复现或排错确实依赖时才保存。

## 5. 切换模型

生成目标不变、只换模型 / 模式时仍属于同一 G 的新 I；Shot 不因供应商变化而变身份。Take 继续在同一 G 内单调递增。

## 6. 用户在外部临时调整

如果用户实际修改了 Prompt、参考或关键设置并生成返回结果，必须把真实输入正式化为正确 I 后再 Receive；不能把结果硬挂到原 I。无长期意义且结果未采用的 UI 调整不必记录。

## 7. 严格可复现项目

只有项目明确要求实验级复现时，再扩展 seed、model revision、完整参数、request metadata、时间戳或成本；这不是所有视频的默认负担。

## 完成标准

创作事实留在资产 / Script / Shot，模型执行事实留在 G/I；正式 Take 可以追溯真实 I，又不会让项目被供应商参数淹没。

# 生成参数与持久化边界

本文件区分“项目长期制作意图”和“一次具体模型执行参数”，避免镜头文件被供应商字段淹没。

## 1. SHOT.md 不拥有模型参数

`SHOT.md` 长期保存：

- 镜头目的；
- 目标时长；
- 摄影；
- 动作；
- 表演；
- 连续性；
- 参考素材职责；
- 硬性约束。

默认不保存：

- API request ID；
- seed；
- sampler；
- guidance；
- 每次重试编号；
- 当前网页 UI 临时开关；
- 供应商内部任务 ID；
- 临时价格；
- 排队状态。

这些内容不是镜头创作事实。

## 2. 长期提示词保存语义，不保存 UI 快照

`prompt_vNN.md` 保存当前可复用的生成文本与必要模型专用结构。

如果一个参数会改变提示词语义，例如：

- Text to Video / Image to Video；
- 首帧 / 尾帧；
- 参考元素模式；
- 是否生成同步声音；

可以在提示词文件顶部简短标明当前模式。

不要把整个网页表单所有字段复制进长期提示词。

## 3. 一次性生成包保存当前执行需要的设置

生成包任务文件要让用户能够在当前平台真正执行，所以可以写：

- 模型 / 使用入口；
- 生成模式；
- 目标时长；
- 画幅比例；
- 当前输出质量 / 分辨率（确实要用户选择时）；
- 是否启用声音；
- 参考素材上传顺序；
- 当前模型要求的其他必要选项。

这些设置服务**这一批执行**，并不自动成为长期项目事实。

## 4. 动态能力由模型适配器核验

具体模型支持：

- 哪些时长；
- 哪些分辨率；
- 几张参考图；
- 什么模式；
- 什么 endpoint；

由当前模型适配器或当前官方资料核验。

通用视频 Skill 不因为一次平台 UI 显示某个选项，就把它写成长期通用规则。

## 5. 哪些执行参数值得长期保留

只有这些情况值得把参数写回正式项目：

### 复现真的依赖

例如同一模型相同 seed 能稳定复现当前重要画面，而且用户需要后续继续延展。

### 排错真的依赖

例如某个特殊 mode / 强度参数明显导致产品结构错误，需要后续避免。

### 当前采用结果的来源需要说明

可以在 `SHOT.md` 的“当前采用”中简短记录：

```text
模型 / 使用入口：Veo 3.1 / Vertex AI
提示词：prompt_veo_v02.md
执行备注：first + last frame
```

只写对复现、连续性或后续判断真正有意义的部分。

## 6. seed 不是身份系统

即使模型支持 seed，也不能把 seed 当成人物 / 产品一致性的主要来源。

身份仍优先来自：

- 正式设计；
- 已验收长期参考；
- 四视图；
- 产品官方结构；
- 当前模型可靠的 reference 机制。

seed 最多是额外执行控制，不替代身份素材。

## 7. 模型默认值

如果当前平台默认值已经足够，而且用户不需要知道它，不为了“完整记录”把全部默认值写进包。

只有需要用户手动确认 / 改动的设置才进入任务文件。

## 8. 切换模型时

同一镜头从 Runway 换到 Veo / Seedance 等：

- `SHOT.md` 不改；
- 模型专用提示词可以新增对应版本；
- 一次性包更新执行设置；
- 不把前一个模型的字段复制给新模型；
- 当前采用记录只在最终选中某个结果后写实际来源。

## 9. 用户在外部平台临时调整

用户临时改了参数后：

- 结果未采用 → 不必长期记录；
- 结果采用，但参数对后续无意义 → 可以只记模型 / 提示词来源；
- 参数决定了后续可复现性 / 连续性 → 把最小必要说明回写正式记录。

不要让唯一有效设置只存在用户浏览器 UI 或聊天记忆里。

## 10. 严格可复现项目

如果某个项目明确要求完整实验级可复现记录，可以在该项目中扩展：

- seed；
- model revision；
- 完整参数；
- request metadata；
- 时间戳；
- 成本。

这是项目特定要求，不默认强加给所有视频制作。

## 完成标准

长期项目文件主要记录创作与制作事实；一次性生成包包含当前真正需要执行的模型设置；机器参数只有在复现、排错或连续性需要时才进入长期记录。

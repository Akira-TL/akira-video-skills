# 批量生成与放量

用于一个项目需要生成较多人物 / 场景素材或多个视频镜头时。

目标不是固定批次数量，而是先验证最容易失败的组合，再扩大当前已经证明稳定的部分。

## 1. 先做代表样本

在大量同类任务前，优先先验证少量代表性高风险对象，例如：

- 主要角色身份图 / 四视图；
- 主要场景空间参考；
- 真实产品结构最难的角度；
- 主角近景；
- 复杂手物交互；
- 多角色互动；
- 可见对白 / 口型；
- 跨世界转场；
- 复杂摄影；
- 当前模型最可能失败的镜头类型。

不需要每一种都做；只选当前项目真正高风险的代表样本。

## 2. 代表样本先审片

样本回来后先进入 `video-review`。

只有以下基准稳定后才扩大：

- 人物身份；
- 场景结构；
- 产品结构；
- 当前视觉方向；
- 参考素材职责；
- 选定模型 / 生成模式对这类镜头的可用性。

如果代表样本已经持续漂移，不要继续批量生成同一错误组合。

## 3. 批次按依赖与风险分，不按数量分

可以同批的任务：

- 输入已经齐全；
- 彼此不依赖尚未生成的实际出口；
- 使用相同已验收身份 / 场景基准；
- 当前模型 / 参考组合已经在相似任务中证明可用。

应该分批的任务：

- 下游依赖前一镜真实出口；
- 角色 / 场景身份还没稳定；
- 新模型 / 新生成模式第一次使用；
- 高风险产品结构；
- 复杂交互；
- 用户还没确认视觉方向。

## 4. 没有固定批量大小

每批 2 个、5 个或 20 个都可能合理。

批量大小取决于：

- 单个任务成本；
- 当前模型稳定性；
- 人工审片负担；
- 镜头之间依赖；
- 当前失败风险；
- 用户希望一次处理多少。

不要把一个数字写成通用规则。

## 5. 扩批条件

一类生成可以扩大批次时，至少已经知道：

- 正式设计不会再大改；
- 核心长期参考已验收；
- 主要提示词结构有效；
- 当前模型 / 模式能完成核心动作；
- 返回命名 / 归档流程已清楚。

## 6. 停止放量的信号

同一批次中反复出现：

- 相同身份漂移；
- 相同产品结构错误；
- 相同空间错误；
- 相同动作失败；
- 相同声音身份失败；
- 大量候选都需要同一种人工补救；

说明问题可能来自设计、参考、提示词或模型组合。

此时停止继续放量，先按失败分类修上游。

## 7. 更换模型 / 参考基准后重新小样

以下变化发生后，不直接沿用旧批次规模：

- 更换视频模型；
- 更换模型主要版本；
- 更换人物身份基准；
- 重做场景；
- 产品官方素材发生变化；
- 整体视觉方向改变；
- 生成模式发生实质变化。

先用代表镜头重新验证，再决定是否放量。

## 8. 一个一次性生成包可以包含多个任务

一次性生成包本身只是交付容器。

同一个包中可以包含多个当前可执行任务，但：

- 每个任务仍有独立提示词 / 返回文件名；
- 高风险任务如果需要先验证，放到更早批次；
- 依赖未满足的任务不因为“打包方便”被提前放进去。

## 9. 审片节奏

批量返回后优先：

1. 快速检查是否存在系统性硬错误；
2. 如果有，先停止后续同类批次；
3. 再对可用候选做详细选择；
4. 选中的长期参考 / 镜头正式归档；
5. 下一批继续使用已验收基准。

## 10. 成本

用户关心成本时，可以：

- 先低成本草稿；
- 高风险样本先少量；
- 稳定后再最终质量放量。

具体价格、模型档位和调用方式由当前平台 / 模型资料决定，不写死在通用 Skill。

## 完成标准

项目通过小样验证后逐步放量；系统性错误会在昂贵批量生成前被发现，而不是一次生成几十个同样有问题的素材。

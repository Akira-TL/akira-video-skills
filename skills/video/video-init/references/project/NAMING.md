# 视频项目命名

命名目标是稳定身份 + 人类可读，不把供应商、全部参数或状态机塞进文件名。

## 1. 核心对象 ID

- `V001`：一支独立交付视频 / 一集；
- `G001`：一个 scope 内的 Generation；
- `I01`：某个 G 的正式 Input Version；
- `take01`：某个 G 内可独立 Review 的候选结果；
- `SC01`：叙事场景 / 场次；
- `SH010`：最终叙事 / 剪辑 Shot；
- `CHR01` / `LOC01` / `PROP01` / `PROD01`：人物 / 地点 / 道具 / 真实产品。

只创建真实需要的 ID。

## 2. 视频目录助记后缀

物理目录可写 `V001_档案室钥匙/`，但正式身份只认 `V001`。Agent / 文件之间引用不保存旧后缀；通过 ID 找当前目录。改标题通常不改目录，必要时改后缀也不影响引用。

Generation 同理可以有人类目录标签，但正式引用只写当前 scope + `Gxxx`。

## 3. Generation 作用域

同一 V 内可简写 `G003`；跨视频写 `V001/G003`；共享资产 Generation 写 `shared/G003`。临时包路径带 scope 和 I：`.tmp/V001/G003_I02/`、`.tmp/shared/G003_I02/`。

## 4. Prompt 与 Input Version

正式 Prompt 只存在对应 I，例如 `prompt_i01.md`、`prompt_i02.md`。切换模型、替换参考或修改关键执行输入但目标不变时通常新建 I，不再使用 `prompt_veo_v01` / `prompt_seedance_v01` 等供应商文件树来表达身份。

## 5. Take

Take 在一个 G 内单调递增，切换 I 不重置：`take01.png`、`take02.mp4`、`take03/`。普通候选是单媒体文件；确实由视频、音轨、字幕等配套文件组成时才使用 `takeNN/` 目录。Take 编号不表示平台生成顺序。

## 6. 资产版本

正式投入生成的二进制参考从 `v01` 起固定，例如 `CHR01_ref_v01.png`、`LOC01_four-view_v02.png`。新参考 / 人工处理产生新版本，不覆盖已经投入生产的文件。文本设计通常使用稳定对象文件名并由 Git 保存历史。

## 7. Shot

默认使用留空编号 `SH010`、`SH020`，需要场景上下文时可写 `SC01_SH010`。简单视频只在唯一 Shot 表维护，不强制目录；个别复杂 Shot 需要独立资料时才建立对应记录。

## 8. 最终导出

多语言 / 多画幅只有真实并存时加明确后缀，例如 `master.en-US.mp4`、`master_vertical.en-US.mp4`。不要为了未来可能本地化提前给所有文件加语言后缀；只有一个语言版本时继续使用最短名称。不要使用 `final2`、`new_final`、`real_final` 这类无法判断关系的名字。

## 9. 文件名不承担的内容

默认不把供应商、模型名、seed、FPS、分辨率、全部参考或 Prompt hash 塞进媒体文件名。这些有长期价值时写入对应 I / 交付记录。

# AI 视频制作流程

本流程描述完整项目常见依赖关系，不是所有项目必须顺序执行的固定阶段表。

已有项目先读取 `VIDEO.md` 和当前实际文件，从当前工作继续；已经完成的脚本、设计、素材和镜头不重新生成。

## 1. 新项目入口

先在 `VIDEO.md` 固定整片级信息：

- 视频目标；
- 上游来源；
- 目标时长 / 画幅 / 平台；
- 必须遵守的客户、比赛、品牌或素材限制；
- 当前真正已知的视觉 / 模型 / 交付决定。

只记录会影响制作的信息，不为了模板完整填空。

## 2. 上游内容 → 视频脚本

有小说、章节、故事或 brief 时进入 `video-script`。

需要做的不是把原文搬进 `video/`，而是形成当前视频的：

- 改编范围；
- 故事 / 信息结构；
- 角色本片表演定义；
- 场次；
- 镜头总览。

广告项目先由 `video-advertising` 固定具体产品事实；产品怎样进入故事还没决定时，先比较简短因果候选，不直接写完整广告故事。

没有剧情的产品镜头、纯视觉视频或用户已经给出完整镜头时，可以跳过不适用的脚本工作。

## 3. 视觉与声音设计

角色 / 场景还只有功能描述时进入 `video-design`：

- 先确定整片视觉方向（需要时）；
- 设计角色具体外形、服装、材质和识别点；
- 设计场景空间、材质、色彩和光线；
- 多世界 / 机械 / 空间关系按需展开。

角色需要跨镜头稳定声音身份时进入 `video-audio`。

### 需要用户决定的创意分叉

当上游资料没有答案，而当前选择会明显改变故事、角色外形、世界视觉或广告方向时：

- 优先给少量真正不同的方案和差异；
- 用户已经授权 Agent 自主决定时可以选择一项并记录；
- 没有授权且选择会显著改变作品时，先让用户决定，再批量生成素材。

不要把“随机第一次生成出来的样子”自动升级为角色设计。

## 4. 规划复用素材

进入 `video-materials`，从真实脚本 / 镜头需求反推：

- 哪些人物必须有稳定身份图；
- 哪些场景需要长期空间参考；
- 哪些道具 / 产品结构必须锁定；
- 哪些状态必须区分；
- 哪些声音需要跨镜头复用。

只生成真正会用的长期素材。

## 5. 第一批外部生成：长期素材

由 `video-generation`：

1. 编写 / 更新正式长期生图或声音提示词；
2. 需要四视图时叠加严格模板；
3. 根据上游依赖整理当前可执行的一次性生成包；
4. 所有包只放项目 `.tmp/`；
5. 必要时压成 zip。

### 交给用户时

Agent 的回复只需要明确：

- 当前包位于 ForgeRelay 项目中的什么路径；
- 这批要生成什么；
- 是否有推荐顺序；
- 生成后按什么文件名返回。

不要要求用户再去项目其他目录寻找缺失提示词 / 图片。

到这里如果实际生成必须由用户在外部平台完成，就停止推进依赖这些结果的下游工作；不能假装已经生成。

## 6. 素材返回 → 审片 → 正式归档

用户把图片 / 声音返回后：

1. 暂存在当前包 `returns/`（需要时）；
2. `video-review` 基于实际 artifact 检查；
3. 多候选先选中一个；
4. 合格结果归入 `video/materials/`；
5. 驳回时先修改正式设计 / 提示词，再重新打包；
6. 当前包没有唯一信息后删除。

长期角色 / 场景参考没有通过审片前，不拿它继续批量生成视频。

## 7. 镜头制作

进入 `video-shot`：

- 从 `SHOTS.md` 展开当前镜头；
- 明确镜头目的、动作、摄影、声音和连续性；
- 引用已经验收的复用素材；
- 复杂镜头按需预演 / 分镜；
- 通过镜头生成前检查。

不要求一次把整片所有 `SHOT.md` 都写完。可以按用户当前想生成的一组镜头逐批推进。

## 8. 第二批及后续外部生成：视频镜头

由 `video-generation`：

1. 从 `SHOT.md` 编译长期视频提示词；
2. 当前视频模型有适配器时按需加载；
3. 只带最小充分参考集；
4. 为每个镜头预留下一组未使用的生成结果编号；
5. 按依赖关系打包当前可执行镜头。

如果后一个镜头必须依赖前一个镜头的真实出口，先生成 / 审核前一个镜头，再打后一个镜头的包。

## 9. 视频返回 → 选择当前采用结果

用户返回视频后进入 `video-review`：

- 查看实际完整视频；
- 检查镜头目的、动作、身份、结构、空间、声音；
- 记录当前采用结果、提示词、必要的模型入口；
- 记录实际出口与计划出口的可接受偏差；
- 决定采用、调整后续、后期修复、重新生成或重写上游定义。

下一镜头连续性以当前采用结果的实际可见出口为基础，但错误身份 / 产品结构 / 剧情事实不能因为“已经生成”升级成正式事实。

## 10. 循环推进

之后按真实依赖循环：

镜头定义
→ 一次性生成包
→ 用户生成
→ 返回审片
→ 当前采用结果 / 实际出口
→ 下一组镜头。

不要求一次完成整片所有镜头，也不要求每轮重新读取全部项目文件。

## 11. 整片后期

已有足够采用镜头后进入 `video-editing`：

- 建立最小 `video/edit/`；
- 粗剪故事 / 信息；
- 调整镜头节奏与动作切点；
- 处理音乐、声音、字幕、Logo、产品文字；
- 对明显可后期解决的问题不重新生成视频。

如果粗剪暴露出脚本或镜头本身的问题，回到正式归属文件修复。

## 12. 最终验收

基于真实成片从头到尾执行最终检查。

只有当前执行器实际能够查看 / 播放 / 听到的维度才可以声明已验收；未检查声音、字幕或完整时间线时明确保留未验收项。

## 13. 结束条件

一轮会话可以在这些自然边界结束：

- 当前用户要求的制作任务已经完成；
- 一次性生成包已交给用户，后续真实依赖用户返回结果；
- 存在需要用户创意决策的显著分叉；
- 缺少产品事实、授权素材或其他真实 blocker；
- 当前成片和交付已经完成。

不要仅仅因为完成了某个内部 Skill 就机械结束；也不要在用户外部生成尚未发生时继续假装推进下游。

## 核心原则

完整项目是依赖图，不是固定流水线：

来源 / 目标
→（按需）脚本 / 产品事实
→（按需）视觉 / 声音设计
→ 复用素材
→ 镜头
→ 一次性生成包
→ 用户实际生成
→ 审片 / 当前采用结果
→ 后续镜头或整片后期。

任何已经存在、已验收的上游对象都直接复用。

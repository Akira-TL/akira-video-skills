# 外部生成等待与恢复

当 Agent 已经整理好一次性生成包，需要用户在外部平台实际生成，再把结果带回来时使用。

这是正常的人机协作边界，不是失败。

## 1. 交付生成包时

Agent 至少确认：

- 当前包实际存在于项目 `.tmp/`；
- 包内任务是当前输入已齐全的可执行任务；
- README 已写生成目标、顺序、上传素材、返回文件名和重点检查；
- 包外没有当前任务必须依赖但用户不知道去哪里找的素材。

如果需要 zip，也只在同一项目 `.tmp/` 中生成。

## 2. VIDEO.md 怎么记录等待状态

只记录最短可恢复摘要，例如：

```markdown
## 当前工作

等待用户完成 SC01 第一批视频生成。

生成包：`.tmp/SC01-generation-pack/`
预期返回：
- SC01_SH010_take03.mp4
- SC01_SH020_take02.mp4

返回后：先进入 `video-review`，再决定 SC01_SH030 是否可以打包。

## 阻塞项

- SC01_SH030 依赖 SC01_SH020 的实际出口，当前等待外部生成结果。
```

不把完整提示词、参考素材清单和生成参数复制进 `VIDEO.md`。

## 3. 等待期间不要假装继续

如果下游任务真实依赖尚未返回的媒体：

- 不编造生成结果；
- 不把计划出口当实际出口；
- 不声明审片通过；
- 不继续打依赖它的下游包。

可以继续做与该结果无关的独立镜头 / 设计 / 后期准备，前提是用户当前目标允许。

## 4. 下一轮会话恢复

先读取：

1. `VIDEO.md` 当前工作 / blocker；
2. 对应 `.tmp/<pack>/README.md`；
3. `returns/` 是否已有返回；
4. 正式项目目录是否已经有人手工归档过结果。

然后判断：

- **还没返回** → 保持等待，不重复创建同一个包；
- **部分返回** → 先处理已有结果，明确还缺什么；
- **全部返回** → 进入审片 / 归档；
- **用户放弃该批** → 清理旧包，回正式来源调整；
- **用户在外部改了提示词 / 参考** → 把真正决定保留的改动回写正式归属文件。

## 5. 不重复打包

如果现有包内容仍然正确，不因为换了一轮会话就创建：

`SC01-generation-pack-v2/`

只有正式设计 / 提示词 / 输入素材已经改变，或旧包损坏 / 不完整时才重新打包。

重新打包时先确认旧包中没有尚未归档的返回结果。

## 6. 部分返回

用户可能只先返回一部分任务。

例如：

- CHR01 身份图返回；
- LOC01 场景图尚未生成。

可以先审片 / 归档 CHR01；

但依赖 LOC01 的视频镜头仍不能继续。

不要要求用户为了“一批必须整体完成”重新上传已经处理好的结果。

## 7. 返回文件映射

优先依赖包 README 中已经约定的文件名。

如果平台改名：

- 一对一关系明确 → 可以整理；
- 多个文件归属不明确 → 向用户确认；
- 不按上传顺序或“看起来像”猜归属。

## 8. 外部临时改动

用户在平台界面临时修改：

- 提示词；
- 参考图；
- 时长；
- 模型 / 模式；

如果该改动只是一次尝试且没有长期意义，可以只用于当前生成。

如果最终采用结果依赖这个改动，而且下一轮还需要复现 / 延续：

先把必要改动写回正式提示词 / `SHOT.md` / 模型选择记录，再清理临时包。

## 9. 结果全部归档后

1. 更新对应长期素材 / `SHOT.md`；
2. `VIDEO.md` 清掉已解决的等待 blocker；
3. 把“当前工作”切到新的真实任务；
4. 确认 `.tmp` 包没有唯一信息；
5. 删除包和 zip。

## 10. 用户回复需要包含什么

把包交给用户时，Agent 的对话回复至少简短写清：

- 包在哪里；
- 这批做什么；
- 用户需要返回哪些文件；
- 返回后下一步是什么。

不要说“后台继续处理”或暗示结果未返回时系统会自动推进。

## 完成标准

外部生成形成清楚可恢复的人机断点：下一轮无需聊天历史也知道在等什么；结果未回来时不假装完成，结果回来后也不会重复打包或丢失正式归档。

# 视频项目命名

命名目标是让人一眼知道对象是什么，同时不给文件名塞入数据库式元数据。

## 1. 稳定对象 ID

默认可使用：

- `CHR01`：角色；
- `LOC01`：长期场景 / 地点；
- `PROP01`：道具；
- `PROD01`：具体产品；
- `CH01`：只有视频制作真实启用章节层级时使用；
- `SC01`：剧本场次 / 场景编号；
- `SH010`：镜头。

简单项目只使用真实需要的 ID，不要求全部存在。

### 场次与地点不同

`SC01` 表示剧本里的一个场次 / 连续叙事单元；`LOC01` 表示可以跨场次复用的地点视觉设计。

例如：

- `SC01`：早晨，厨房，角色第一次发现问题；
- `SC05`：夜晚，再次回到同一个厨房；
- 两个场次都可以引用同一个 `LOC01`，只在镜头 / 场次中改变时间、临时道具和当前状态。

### 道具与产品不同

`PROP01` 是故事道具；`PROD01` 是需要保持具体官方身份、结构和事实边界的产品。普通故事道具不因为“看起来像商品”自动升级为广告产品对象。

## 2. 镜头 ID

有明确场次时：

`SC01_SH010`
`SC01_SH020`

没有场次的简单项目可以直接：

`SH010`
`SH020`

镜头编号默认留间隔，便于以后插入 `SH015` 或 `SH025`，不因为新增一个镜头重排后面所有身份。

## 3. 复用素材

文件名优先采用：

`<object-id>_<用途或状态>.<ext>`

例如：

`CHR01_design.md`
`CHR01_prompt.md`
`CHR01_identity.png`
`CHR01_four-view.png`
`CHR01_costume-a.png`
`CHR01_voice.md`
`CHR01_voice-reference.wav`
`LOC01_design.md`
`LOC01_four-view.png`
`LOC01_kitchen.png`
`PROP01_damaged.png`
`PROD01_truth.md`
`PROD01_official-front.png`

用途 / 状态只有真的需要区分时才写。

## 4. 提示词版本

长期文本普通修改由 Git 保存历史。

只有同一时刻确实需要保留多个可比较提示词时才使用：

`prompt_v01.md`
`prompt_v02.md`

`prompt_vNN.md` 默认表示当前镜头的主视频提示词。

同一镜头还需要生成首帧、尾帧或分镜 / 关键帧时，图片提示词按用途命名，例如：

`start-frame_prompt.md`
`end-frame_prompt.md`
`storyboard_prompt.md`

只有这些图片提示词本身需要同时保留多个可比较版本时，才使用 `start-frame_prompt_v01.md` 这类版本号。

当前镜头同时维护多个视频模型的不同编译版本时，才增加清楚的模型后缀，例如：

`prompt_veo_v01.md`
`prompt_runway_v01.md`
`prompt_seedance_v01.md`

只有一个模型路线时继续使用最短的 `prompt_vNN.md`，不要为了“以后可能换模型”提前扩展命名。

### 多画幅生成版本

只有同一个镜头确实同时保留多个独立画幅源时，才增加画幅用途后缀，例如：

`prompt_vertical_v01.md`
`take03_vertical.mp4`

只有一个主画幅，或者竖版只是后期安全裁切时，不给镜头源文件增加画幅后缀。

不要因为每改一句就创建新版本文件。

## 5. 图片候选

同一长期图片一次返回多个候选时，候选只在一次性生成包的 `returns/` 暂存，例如：

`CHR01_identity_take01.png`
`CHR01_identity_take02.png`

审片选中后再归档成长期稳定名：

`CHR01_identity.png`

没有被选中的候选默认随临时包清理；如果用户明确要长期保留多个真正不同的状态 / 方案，再给它们明确状态名或用途名，而不是长期留下 `takeNN`。

## 6. 镜头专属图片

首帧、尾帧、分镜草图 / 关键帧等只服务某一个镜头的图片跟随该镜头，例如：

`start-frame.png`
`end-frame.png`
`storyboard.png`
`keyframe-01.png`

如果这些文件需要离开镜头目录交给用户外部生成 / 传回，使用完整镜头 ID 保持归属，例如：

`SC01_SH010_start-frame.png`

多个候选先在一次性生成包的 `returns/` 使用 `_takeNN` 暂存，选中后再整理成稳定镜头内文件名。

这些图片只有在多个镜头确实复用时才升级到 `video/materials/`。

## 7. 视频生成结果

在镜头目录内：

`take01.mp4`
`take02.mp4`

生成结果编号在同一个镜头内单调递增。修改提示词或切换模型后也不从 `take01` 重新开始；新一轮生成先查看已有文件并分配下一个未使用编号，避免覆盖历史结果。

文件离开镜头目录，需要用户从外部平台传回时，可以使用完整归属：

`SC01_SH010_take01.mp4`

导回项目后可按镜头目录现有简洁命名整理。

## 8. 多语言版本

只有同一项目中真正并存多个语言版本时，才增加语言后缀。优先使用 IETF BCP 47 风格语言标签，例如：

`subtitles.en-US.srt`
`voiceover.en-US.wav`
`master.en-US.mp4`
`master.ja-JP.mp4`
`master_vertical.en-US.mp4`

只有一个语言版本时继续使用最短名称，例如：

`master.mp4`
`voiceover.wav`

不要为了未来可能本地化提前给所有文件加语言后缀。

同一语言的镜头源视频如果画面本身不需要变化，继续复用原镜头，不创建语言专属 `takeNN`；只有口型、场景内文字或其他视觉内容必须变化时才建立语言专属生成源。

## 9. 禁止 final 链

不要使用：

`final.png`
`final2.mp4`
`new_final.mp4`
`real_final.mp4`

当前采用哪个生成结果由 `SHOT.md` 或等价明确记录表示；整片当前导出也由 Git / 后期工程和清楚版本关系管理，不靠文件名猜。

## 10. 文件名不承担的内容

默认不把以下内容塞进媒体文件名：

- 模型名称；
- 供应商；
- seed；
- 分辨率；
- FPS；
- 全部参考素材；
- 提示词哈希。

这些只有在真实工作流需要长期保存时才进入对应说明，而不是污染所有文件名。

## 完成标准

用户不看数据库、不读隐藏 metadata，仅凭目录和文件名就能判断对象归属；同时文件名不会因为每次模型参数变化而不断膨胀。

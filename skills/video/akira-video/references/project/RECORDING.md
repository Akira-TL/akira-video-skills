# 制作记录与持久化边界

本文件规定哪些决定需要写进项目，写到哪里，以及哪些只属于当前讨论 / 临时生成。

目标是让下一位 Agent 能恢复制作，又不把项目变成操作日志。

## 1. 聊天不是长期项目记录

一个决定只有真正影响后续制作时，才需要写进正式归属文件。

例如用户在聊天里确认：

- 主角最终选择灰色长风衣；
- 广告故事使用方案 B；
- 产品背面不允许生成；
- SC01_SH020 采用 take03；

对应决定应写到角色设计、脚本 / 产品事实、镜头当前采用等正式位置，而不是只依赖聊天历史。

## 2. VIDEO.md 只保存整片级当前摘要

适合进入 `VIDEO.md`：

- 当前视频目标 / 交付要求；
- 上游来源与关键限制；
- 当前主要视觉方向；
- 整片级关键决定；
- 当前正在推进的工作；
- 当前真实阻塞项；
- 当前主要导航入口。

不适合进入 `VIDEO.md`：

- 每个提示词版本；
- 每个生成结果；
- 每轮模型参数；
- 每个失败原因；
- 临时生成包内容；
- 已经失效的历史决定。

## 3. 具体决定写到具体归属文件

| 决定 | 长期归属 |
| --- | --- |
| 故事 / 对白 / 场次 | `video/script/` |
| 角色视觉设计 | `CHRxx_design.md` |
| 地点视觉设计 | `LOCxx_design.md` |
| 产品事实 | `PRODxx_truth.md` |
| 角色声音身份 | `video/materials/voices/` |
| 长期参考 / 提示词 | `video/materials/` 对应对象 |
| 单镜头摄影 / 动作 / 连续性 | 对应 `SHOT.md` |
| 当前采用生成结果 / 实际出口 | 对应 `SHOT.md` |
| 整片剪辑 / 图文 / 混音 | `video/edit/` 工程 |
| 一次性执行说明 | `.tmp/`，用后删除 |

## 4. VIDEO.md 更新触发

以下变化通常需要更新 `VIDEO.md`：

- 视频目标 / 交付要求变化；
- 主要改编范围变化；
- 整片视觉方向确认或大改；
- 当前工作切换到新的主要任务；
- 新阻塞项出现；
- 阻塞项已解决；
- 当前后期 / 成片入口变化；
- 一个影响大量后续工作的项目级决定被确认。

以下变化通常不需要更新：

- `prompt_v02` 改一句话；
- 新增一个失败 take；
- 某镜头轻微后期修复；
- 一张未采用候选图；
- 当前模型临时调一个参数。

## 5. 当前工作不是历史日志

`VIDEO.md` 的“当前工作”写现在真正推进什么。

当任务完成 / 转移：

- 更新或替换旧内容；
- 不在下面一直追加“已完成 1 / 已完成 2 / 已完成 3”。

需要历史时看 Git 和正式产物。

## 6. Blocker 必须真实阻塞

适合写阻塞项：

- 缺官方产品资料；
- 缺用户必须决定的核心视觉方向；
- 外部生成结果尚未返回且下游依赖它；
- 来源 / 使用权限不明确导致不能交付；
- 关键上游事实冲突。

不适合：

- “还没开始下一镜”；
- “可以再优化”；
- “目前有两个普通候选”；
- Agent 自己还没做完的普通工作。

## 7. 当前采用与实际出口只写镜头

每个镜头的：

- 当前采用结果；
- 对应提示词；
- 模型 / 使用入口（必要时）；
- 实际出口；
- 可接受偏差；
- 后期修复项；

全部留在当前 `SHOT.md`。

`VIDEO.md` 只在它变成整片阻塞项 / 关键里程碑时才提一句。

## 8. 临时生成包不反写项目

`.tmp/` 里的 README 或任务文件不是项目事实源。

用户在外部平台临时改了一个提示词，如果这个修改最终决定保留：

1. 回写对应长期提示词 / 镜头定义；
2. 再把生成结果归档；
3. 不让唯一正确版本只留在临时包或平台聊天框里。

## 9. 决策候选与正式决定

仍在比较的方案可以：

- 留在当前讨论；
- 临时变体文件；
- `.tmp/` 候选包。

只有选定后才进入正式设计 / 脚本。

不要把 A/B/C 三个互斥方向全写进正式 `CHR01_design.md`，让后续 Agent 自己猜当前是哪一个。

## 10. 不记录无意义机器细节

模型参数只有在后续复现、比较或排错真的需要时才长期记录。

不默认持久化：

- 每个 seed；
- 每次 API request ID；
- 每个时间戳；
- 每个临时成本；
- 每个缓存文件。

如果某个项目确实需要严格可复现生成，再按该项目要求扩展记录，不把这种需求强加给所有视频。

## 11. 会话结束前

完成当前有边界工作后检查：

- 有无刚确认但还只存在聊天里的重要决定；
- `VIDEO.md` 当前工作是否仍准确；
- 当前镜头采用结果是否已写入 `SHOT.md`；
- 外部生成包是否已交付 / 等待用户；
- 临时包是否存在尚未归档的唯一结果。

只补真正缺失的持久化，不做“为了完整”全项目重写。

## 完成标准

下一位 Agent 不依赖聊天历史也能恢复当前制作；同时项目文件保持简洁，不被提示词迭代和生成日志淹没。

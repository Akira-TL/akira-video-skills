# 镜头预演与分镜

预演 / 分镜用于在昂贵视频生成前解决构图、走位、空间和剪辑关系。它是按需工具，不是每个镜头必须多做一张图。

## 1. 什么时候值得做

以下情况优先考虑预演：

- 多角色走位复杂；
- 人物与产品 / 机械有精确交互；
- 摄影机路径复杂；
- 相邻镜头空间连续性容易出错；
- 首帧 / 尾帧需要明确控制；
- 一个场次包含多个镜头，先看整体剪辑关系更省生成成本；
- 转场依赖动作、形状、颜色或构图匹配。

简单固定机位、单主体、动作明确的镜头可以直接进入生成，不为了流程完整强制做分镜。

## 2. 预演解决什么

优先解决：

- 画面里谁在哪里；
- 主体朝向；
- 摄影机位置和观察方向；
- 主要动作起点 / 终点；
- 产品 / 道具怎样进入画面；
- 相邻镜头从哪里切；
- 哪些空间关系必须持续。

预演不是最终美术图，不要求材质、皮肤、光效全部精修。

## 3. 存放位置

只服务一个镜头：放对应镜头目录，例如：

`storyboard.png`
`start-frame.png`
`end-frame.png`
`keyframe-01.png`

整片 / 一个场次的总览分镜确实有用时，可以在 `video/script/` 放一张人类可读总览图，例如 `storyboard.png`；不需要额外创建 storyboard 目录。

## 4. 分镜不等于身份参考

粗分镜、草图和低质量预演图通常只负责：

- 构图；
- 站位；
- 动作；
- 摄影；
- 剪辑关系。

除非它本身就是已经验收的角色 / 场景参考，否则不要把分镜图同时当人物脸、服装或产品结构的身份来源。

生成包里如果同时包含身份图和分镜图，要明确写：

- 身份图负责人物身份；
- 分镜图只负责构图 / 动作。

## 5. 首帧与尾帧

当前视频模型支持首帧 / 尾帧控制时：

- 首帧必须符合 Continuity In；
- 尾帧表达计划的 Continuity Out；
- 两张图的身份、服装、产品、场景结构不能互相冲突；
- 提示词主要说明从首帧到尾帧之间怎样运动和变化。

尾帧只是计划出口；真实生成回来后仍以采用结果的实际出口为下一镜头依据。

## 6. 剪辑余量

如果镜头不是必须一开始就处于高速动作中，尽量给主要动作前后留可剪的稳定时刻：

- 动作前短暂建立；
- 动作完成后的反应 / 定格；
- 明确的结束姿势。

需要动作剪辑时，则明确前一镜和后一镜各自承担动作哪一部分，不让两个镜头都从完整动作头演到尾。

## 7. 动态分镜（Animatic）

当一个视频有较多镜头、对白、音乐节奏或严格总时长，而且直接生成全部视频成本较高时，可以先做轻量动态分镜（Animatic）。

最小 Animatic 可以只包含：

- 分镜图 / 首帧 / 简单占位图；
- 按目标时长排列的镜头；
- 临时对白 / 旁白（需要时）；
- 临时音乐 / 节拍（需要时）。

它主要验证：

- 镜头顺序是否能理解；
- 总时长是否合理；
- 对白是否放得下；
- 反应是否太短 / 太长；
- 产品是否有足够可读时间；
- 转折 / 包袱 / 片尾是否有空间；
- 哪些镜头其实重复或缺失。

Animatic 不是最终成片，也不需要把每张图做成高质量概念画。

### 存放

如果只是一次性节奏验证，可以放 `.tmp/` 并在确认后删除。

如果它是当前项目长期有用的制作基准，可以直接放 `video/script/animatic.mp4`；不要为此新建一级 preproduction / storyboard 目录。

### 发现问题时

优先修改正式来源：

- 故事 / 对白问题 → `video-script`；
- 镜头数量 / 作用问题 → `SHOTS.md` / `video-shot`；
- 总时长问题 → `DURATION-BUDGET.md` 对应规划；
- 产品可读性问题 → 广告 / 镜头设计。

不要先把高成本视频全生成，再用剪辑强救一个 Animatic 已经暴露的结构问题。

## 8. 预演审查

进入正式视频生成前检查：

- 空间关系是否自洽；
- 角色和产品是否能看清；
- 摄影机是否有合理位置；
- 动作是否能在目标时长完成；
- 相邻镜头是否有自然切点；
- 预演是否与长期角色 / 场景设计冲突。

## 完成标准

预演只解决正式生成前最昂贵的未知问题；它不会额外制造一套角色身份、场景事实或复杂目录。

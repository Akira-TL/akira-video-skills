# 多候选选择

当一次图片、声音或视频生成返回多个候选时使用。

目标不是“在一堆结果里挑最好看的”，而是先判断是否有任何候选满足当前正式制作要求。

## 1. 所有候选使用同一评价依据

比较前固定：

- 当前正式设计；
- 当前提示词；
- 当前镜头定义；
- 已验收长期参考；
- 产品事实（适用时）；
- 相邻镜头连续性（适用时）。

不要因为看到某个候选很惊艳，就临时改变评价标准。

## 2. 先淘汰硬错误

任何候选出现以下问题时，优先淘汰：

- 人物身份明显错误；
- 产品结构 / 型号错误；
- 关键空间关系错误；
- 违反剧情事实；
- 四视图不是同一对象 / 同一空间；
- 必须完成的动作完全失败；
- 声音变成另一个角色。

硬错误不能由“画面更漂亮”抵消。

## 3. 再比较制作适配度

剩余候选按当前任务比较：

### 长期图片

- 与设计和已有身份参考一致；
- 结构稳定；
- 作为后续参考是否清楚；
- 背景 / 姿势是否会污染身份；
- 四视图是否合格。

### 视频镜头

- 是否完成镜头目的；
- 动作和表演；
- 摄影；
- 连续性入口 / 实际出口；
- 声音；
- 后期可修复程度。

### 声音

- 身份 / 音色；
- 情绪；
- 发音；
- 自然时长；
- 是否适合作为长期声音参考。

## 4. 最后才比较美感

多个候选都满足硬约束和制作功能后，再比较：

- 构图；
- 表演细节；
- 光线；
- 节奏；
- 质感；
- 与整片视觉方向的统一性。

## 5. “最好的一条”也可以全部不合格

如果所有候选都违反关键要求，结论是重新生成 / 重写上游，而不是因为必须选一个就接受“最不差”的候选。

多个候选反复出现同一失败时，检查设计、参考、镜头负载和提示词，不继续盲抽样。

## 6. 不因候选自动重设计

某个候选出现了一个原设计没有的新发型、新服装、新产品结构或新场景布局，即使很漂亮，也不能直接把它升级为长期身份。

如果用户明确喜欢并决定改设计：

1. 先更新正式设计 / 事实来源允许的内容；
2. 再把它作为新的长期参考；
3. 检查已完成镜头是否因此产生连续性影响。

## 7. 选择结果

图片 / 声音候选：只有选中的候选进入长期稳定文件名。

视频镜头：在 `SHOT.md` 的当前采用记录里写明选中的生成结果、对应提示词和必要的实际出口。

未选候选默认留在一次性生成包等待清理；只有用户明确需要保留对比材料时才长期保存。

## 完成标准

选择结果能够说明“为什么它满足正式制作要求”，而不是只有“我觉得这张最好看”。

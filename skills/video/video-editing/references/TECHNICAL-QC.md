# 成片技术检查

用于最终导出或正式交付前确认媒体文件本身可用。它补充内容 QC，不替代从头到尾观看成片。

## 1. 文件基本可用

至少确认：

- 文件真实存在且大小合理；
- 容器能够正常打开 / 解码；
- 视频时长不是 0；
- 没有明显损坏或提前截断；
- 交付文件名与当前用途一致。

如果环境具备 `ffprobe` / FFmpeg，可以优先用确定性工具读取媒体属性和做解码错误检查；如果没有，就使用当前剪辑 / 播放工具提供的实际媒体信息。

## 2. 对照 VIDEO.md 交付要求

逐项核对适用内容：

- 画幅比例；
- 分辨率；
- 是否保持正确像素比例、没有非等比拉伸；
- 时长范围；
- 帧率（如果交付有明确要求）；
- 文件格式 / 编码（如果明确要求）；
- 是否需要无字幕版 / 字幕版；
- 是否需要横版 / 竖版等多个变体；
- 是否需要音轨。

不从“通常广告都这样”猜交付参数，只检查 `VIDEO.md`、客户、比赛或平台当前明确要求。源素材经过放大后可以满足输出尺寸要求，但如果项目需要区分原生分辨率与后期放大，应明确记录，不把后期放大表述成模型原生输出。

## 3. 音轨

要求声音的成片确认：

- 实际存在音频流；
- 声音没有意外静音；
- 对白、音乐、音效大体处于合理电平；
- 左右声道 / 声音布局没有明显错误；
- 片头片尾没有异常爆音或被截断。

专业响度标准只有当前交付明确要求时才按对应标准执行，不在通用 Skill 写死一个数值。

## 4. 多个交付文件分别检查

`master.mp4` 正确不代表 `master_vertical.mp4`、字幕版或其他导出自动正确。

每一个真正要交付的文件至少分别核对：

- 可解码；
- 时长；
- 画幅 / 分辨率；
- 音轨；
- 对应内容是否正确。

## 5. 可重建文件与正式交付

缓存、代理、预览和临时渲染不当成正式成片。

正式交付文件放在当前项目约定的 `video/edit/`，并使用有意义的 master / review / 用途命名；不把软件缓存当作唯一最终输出。

## 6. 不能检查就明确保留

如果当前执行器无法读取编码信息、播放完整文件或听声音：

- 明确写出未检查项；
- 不宣称“技术 QC 全部通过”；
- 可以把需要用户 / 后期软件确认的条目列给用户。

## 7. 完成标准

每个正式交付文件不仅内容通过审片，而且媒体本身能正常使用，并与 `VIDEO.md` 当前交付要求一致。
